# PRD — 投标技术标智能撰写系统（技术响应文件生成）

> 文档状态：草稿 v0.4
> 编写日期：2026-09-22（v0.4：知识库采用 RAGFlow 自带向量引擎，业务关系库改用 MySQL，不再使用 openGauss DataVec）
> 业务领域：IT 技术类投标（技术标 / 技术响应文件）



***

## 1. 项目概述

### 1.1 背景与问题

投标工作中，**技术响应文件（技术标）** 需要逐条响应招标文件（招标书 + 技术规范书）中的技术需求，当前存在以下痛点：



* **撰写耗时**：逐条需求手工撰写，工作量大、周期长。

* **知识沉淀难**：历史标书、技术规范散落在本地 / 共享盘，难以检索复用，重复劳动。

* **质量不稳定**：不同工程师产出水平参差，响应内容易**超范围**（写到招标未要求的内容）、**缺项漏项**。

* **来源不可追溯**：响应内容依据不明，审核和追溯困难，存在合规风险。

### 1.2 项目目标

构建一个**基于 RAG 检索增强生成 + 确定性工作流编排的 AI 智能文档编辑器**，实现：



1. 解析招标文件，自动提取**技术需求条目清单**。

2. 基于企业知识库（历史标书、技术规范书）逐条生成**多个候选响应**（带来源引用）。

3. **人工逐条挑选 / 修改**，并在 **WYSIWYG 智能编辑器**中精修（光标选中提问/改写/插入替换）。

4. **图片资产库**：保留预设图片 + 元数据，AI 撰写时自动识别并建议插入（人工确认）。

5. **模型-知识库读写隔离**：知识库只读、AI 产出先进草稿、人工审核才入库，防止知识库被污染。

6. 严格**不超范围、来源合规、可追溯**。

7. 定稿内容可**回流知识库**，持续沉淀企业能力。

### 1.3 名词定义



| 名词          | 说明                             |
| ----------- | ------------------------------ |
| 招标文件        | 招标书 + 技术规范书（可能为文件夹、多文件），是需求的来源 |
| 需求条目        | 从招标文件中提取出的、需要逐条响应的技术点          |
| 技术响应文件（技术标） | 最终交付物，逐条响应招标要求的文档              |
| 知识库         | 企业历史标书、技术规范、产品资料等检索素材          |
| RAG         | 检索增强生成：先检索知识库再生成回答             |
| 候选响应        | 针对某条需求生成的多个可选答案，供人工挑选          |

## 2. 用户与角色



| 角色          | 描述      | 核心诉求            |
| ----------- | ------- | --------------- |
| 投标工程师（主用户）  | 系统主要使用者 | 快速获得合规初稿，减少重复劳动 |
| 技术负责人 / 审核人 | 把关质量与合规 | 逐条审核、追溯来源、控制超范围 |
| 知识库管理员      | 维护知识库   | 文档入库、版本管理、合规标注  |

## 3. 核心业务流程



```
①上传招标文件包

（招标书 + 技术规范书，文件夹/多文件）

&#x20;       │

&#x20;       ▼

②解析 → 提取技术需求条目清单（需求列表）

&#x20;       │

&#x20;       ▼

③每条需求 → RAG 检索知识库 → 生成 N 个候选响应（带来源引用）

&#x20;       │

&#x20;       ▼

④推送人工：逐条选择候选 / 修改 / 补充

&#x20;       │

&#x20;       ▼

⑤组装成完整技术响应文件 → 导出交付

&#x20;       │

&#x20;       ▼

⑥定稿内容回流知识库（持续沉淀）
```

**关键交互（需求 3）**：系统**逐条**给出多个候选答案，**人工逐条挑选**，而不是系统一次性输出整篇。人在回路中做最终决策，保证质量与合规。

## 4. 功能需求

### FR-1 招标文件解析与需求提取



* 支持上传单个文件或**文件夹 / 多文件**（招标书、技术规范书，docx/pdf 等）。

* 自动解析文档结构（章节、条款、表格）。

* 提取**技术需求条目清单**，包括：条目内容、所属章节、类型（强制 / 参考 / 一般）、是否涉及具体指标。

* 输出结构化需求列表，供人工确认 / 修正后再进入生成环节。

### FR-2 知识库管理与检索（RAG）



* 企业知识库支持文档入库、解析、结构化切块、向量化。

* 检索采用**混合检索 + 重排**，并按元数据（来源、版本、适用范围）过滤。

* 支持增量更新、版本管理、失效内容管理。
* 技术实现：基于开源 RAGFlow 作为知识库（深度文档理解 + 模板切块 + 混合检索 + 知识库管理）。向量与切块由 RAGFlow 部署自带的文档/向量引擎承载，不再外接独立向量库；业务关系数据（需求/项目/版本/审计日志）使用 MySQL。前端直接提供知识库管理页面，后端代理 RAGFlow 完成全部操作。

### FR-3 多候选生成



* 针对**每一条需求**，基于检索结果生成 **N 个（建议 3 个）候选响应**。

* 每个候选响应必须**标注来源引用**（引用知识库哪份文档、哪个章节）。

* 候选之间尽量差异化（详略、表述、角度），供人工择优。

### FR-4 人工逐条审核工作台



* 以 "需求条目" 为单位的列表式工作台。

* 每条需求展示：需求原文 + 多个候选 + 来源引用。

* 人工支持：选择某个候选 / 修改 / 重新生成 / 跳过（标注待人工处理）。

* 逐条完成后进入组装环节。

### FR-5 文档组装与导出



* 将人工确认后的响应按招标文件章节结构组装。

* 导出为标准 Word（docx）技术响应文件。

* 支持保留来源批注（可选）。

### FR-6 合规与范围约束（核心）



* **严禁超范围**：生成时提示词强约束 "只响应招标要求，不额外发挥"；对超出招标需求的内容做**校验拦截**。

* **来源合规**：所有候选响应必须基于知识库，附引用；无来源支撑的内容标记为 "待人工补充"。

* **可追溯**：最终文档可追溯到每条需求的来源。

### FR-7 知识库内容回流



* 人工定稿的优质响应可一键入知识库，作为后续项目的复用素材。

* 入库内容带元数据（来源项目、适用类型、版本、时间）。

### FR-8 AI 智能编辑器（产品核心，需求2/3）



* 所见即所得（WYSIWYG）文档编辑，保留完整人工编辑能力。

* **光标选中 → AI 操作菜单**：改写 / 润色 / 扩展 / 按招标要求重写 / 补充技术细节 / 插入插图建议。

* AI 生成块带**引用 chip**（点击跳转来源）与**状态**（AI生成/待确认/已确认/人工编辑）。

* 仅人工确认的内容才算定稿；AI 产出先进草稿，不直接覆盖定稿。

* 模型调用分级：内容型（强制只读检索+引用）与自由型（不检索、标注"未引用库"）。

### FR-9 图片资产库（需求1）



* 保留预设图片并支持**元数据标注**（类型/标题/描述/适用范围/来源授权/标签/版本）。

* 撰写时根据需求条目与文档上下文，AI 自动检索图库并**建议插图**（候选图 + 图注），人工确认后插入。

* 仅建议 `自有/已授权` 来源的图片，保障版权合规。

### FR-10 模型-知识库读写隔离（需求4）



* 知识库为**只读受控数据源**，模型经检索门只读访问，不提供写库路径。

* **双数据平面**：权威库（只读）与草稿区（可写不入库）分离。

* AI 产出先进草稿，经人工审核 + 元数据确认后才能入库（唯一写入口）。

* 输出经**校验门**（超范围/无依据/敏感检测），不合格拦截。

## 5. 非功能需求



| 维度   | 要求                                     |
| ---- | -------------------------------------- |
| 性能   | 单条需求生成多候选响应在可接受时间内（目标 ≤ 30s / 条，取决于模型） |
| 部署   | 可部署于公司服务器 / 虚拟机（机房自建，无外部依赖）            |
| 数据合规 | 全部本地部署，投标与知识库数据不出企业环境                  |
| 可用性  | 支持多用户并发（按项目 / 角色权限）                    |
| 可维护性 | 知识库可增量更新，无需全量重建；系统可监控日志                |
| 权限   | 知识库与项目数据按角色 / 项目隔离（可选）                 |



***

## 6. 验收标准（MVP）



| 指标    | 目标                         |
| ----- | -------------------------- |
| 需求提取  | 能从典型招标文件中提取出主要技术需求条目，人工可修正 |
| 检索命中  | 对典型需求能召回相关历史标书内容           |
| 多候选生成 | 每条需求生成 3 个候选，均带来源引用        |
| 超范围率  | 明显超范围内容占比低（初版目标：可被人工校验拦截）  |
| 组装导出  | 能按章节组装并导出 docx             |

> 注：以上为 MVP 验收基线，具体阈值在试点项目后校准。



***

## 7. 范围外（不做）



* 不自动投标、不代替人工做最终决策。

* 不含商务标、价格标、资质文件。

* 不做与投标无关的通用文档生成。

* 不接入外部云服务（数据不出企业）。

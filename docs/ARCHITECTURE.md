> 文档状态：草稿 v0.2
> 编写日期：2026-09-21（v0.2 更新：引入 RAGFlow 引擎 + openGauss DataVec + 解析器选型）
> 更新要点：①RAG 引擎改用开源 RAGFlow；②向量库/元数据改用国产化 openGauss DataVec；③解析器支持 DeepDoc/MinerU/Docling 多选；④前端通过后端代理管理知识库。

│  │ 招标解析模块 │ │ Agent 编排  │ │ 文档组装/导出模块      │  │
│  │ 需求提取    │ │ (工作流)    │ │ (docx 生成)          │  │
│  └────────────┘ └────────────┘ └──────────────────────┘  │

│  │   知识库管理代理（KBAgent）→ 调 RAGFlow API/SDK     │   │
│  │   创建/上传/解析/切块/检索，含鉴权、审计、合规过滤      │   │

     │  RAGFlow（RAG引擎）│  │  模型服务    │  │  文档存储      │
     │ DeepDoc/MinerU/  │  │ Qwen3-30B  │  │ 原始文档       │
     │ Docling 解析      │  │ bge-m3     │  │ (MinIO/本地)  │

**原则**：全部组件本地部署于公司机房/VM，数据不出企业环境；向量库采用国产化 openGauss，满足信创合规。

## 2. 技术栈选型

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python | 生态成熟，RAG/LLM 工具链丰富 |
| 生成模型 | Qwen3-30B（本地） | 本机部署，能力足够，数据不出域 |
| **RAG 引擎** | **RAGFlow（开源）** | 深度文档理解 + 模板切块 + 混合检索 + 重排 + 知识库管理，开箱即用 |
| Embedding | bge-m3（本地，bge-large-zh 亦可） | 中文好，支持稠密+稀疏向量 |
| 重排 | bge-reranker（本地） | 精排召回结果，提升检索质量 |
| **向量库** | **openGauss DataVec（≥7.0）** | 国产化，HNSW/IVF/PQ 向量索引 + BM25，一个库管向量与元数据 |
| 关系库 | openGauss（复用，兼容 PostgreSQL） | 存需求清单、项目、元数据、版本 |
| Agent 编排 | LangGraph 或 Dify | 需求提取→检索→生成→组装 的工作流编排 |
| 后端 | FastAPI | 业务 API + 知识库管理代理 + 鉴权/审计 |
| 前端 | Vue/React（工作台） | 审核交互 + 知识库管理页面 |
| 部署 | Docker + Docker Compose | 打包后一键部署到机房 |

## 3. RAG 管线（核心，由 RAGFlow 承载）

> RAGFlow 负责"解析→切块→向量化→检索→重排→知识库管理"的脏活，后端通过其 HTTP API / Python SDK（`ragflow_sdk`）对接，无需自研切块与索引。

### 3.1 文档解析（解析器多选）
RAGFlow 内置 **DeepDoc**（OCR、版面分析、表格识别），并支持**切换更专业的解析器**：

| 解析器 | 适用场景 | 资源要求 | 结论 |
|---|---|---|---|
| **DeepDoc**（默认） | 普通 PDF/Word，跑 MVP | 较低 | 先用它，够用即可 |
| **MinerU** | 复杂表格、公式、扫描件、乱版 PDF | **需 GPU** | 技术规范书表格/扫描件多时用 |
| **Docling**（IBM） | 信创/敏感/无 GPU 环境 | 轻量，CPU 可跑 | 隔离环境首选 |

- 解析后产出：招标文件→需求条目清单；知识库文档→结构化块。
- ⚠️ **换解析器需重新解析全库**，定好再切，避免反复。

### 3.2 结构化切块（痛点①，由 RAGFlow 模板切块承载）
- 按版面/标题层级切分，而非固定字数；每块保留父级上下文。
- 技术规范书/标书建议用 **`manual` 模板**（适配编号条款），表格多的用 `table`，或用 `naive` 起步。
- 表格单独成块、不拆散；支持表格/图片上下文窗口。
- 每块附加**元数据**：来源文档、章节路径、内容类型、适用范围、版本/状态。

```
元数据模型（块 "身份证"）：
  source_doc   : 技术规范书_V2.3.pdf
  section_path : 第3章/3.2/3.2.1
  content_type : 条款 | 表格 | 通用要求
  scope        : IT 系统集成 | 软硬件 | ...
  version      : V2.3
  status       : 有效 | 失效
```

### 3.3 向量化与索引
- RAGFlow 用本地 embedding（bge）编码向量，写入 **openGauss DataVec**（HNSW/PQ 索引）。
- 增量索引：新文档只处理自身，不重建全库。

### 3.4 检索与重排
- **混合检索**：稠密向量（语义）+ BM25/稀疏（专业术语关键词）双路召回。
- **元数据过滤**：检索时用 `metadata_condition` 限定适用范围与版本状态（杜绝旧版/越界）。
- **重排**：召回后由 bge-reranker 精排，取 Top5~8 拼上下文。

### 3.5 生成（多候选，后端 + Qwen3-30B）
- 对**每条需求**，基于 RAGFlow 检索上下文，用 Qwen3-30B 生成 **N=3 个候选响应**。
- 候选差异化（详略/表述/角度）。
- 每个候选**强制标注来源引用**（引用哪份文档/章节，来自检索 chunk 元数据）。

## 4. Agent 工作流（需求提取 → 生成 → 组装）

用 LangGraph（或 Dify）编排有状态工作流：

```
[上传招标包]
   → parse_docs(解析)
   → extract_requirements(提取需求条目清单, LLM)
   → [人工确认需求清单]  ← 状态节点，暂停等人工
   → 对每条需求:
        retrieve(调 RAGFlow 检索，混合+过滤+重排)
        generate_candidates(生成3个候选, 带引用)
        → [人工逐条挑选/修改]  ← 状态节点，暂停等人工
   → assemble(按章节组装)
   → export_docx(导出)
   → feedback_to_kb(定稿回流知识库，经 RAGFlow 入库)
```

**人在回路**：工作流在"需求确认"和"逐条挑选"两处暂停，等待人工，保证质量与合规。

## 5. 知识库管理（痛点②，前端直接管理）

**前端提供知识库管理页面，后端做代理，驱动 RAGFlow 完成全部操作**（不使用 RAGFlow 自带 UI）：

| 前端页面 | 后端端点（代理） | RAGFlow 能力 |
|---|---|---|
| 知识库列表 | `POST/GET /api/kb/datasets` | 创建/列出数据集 |
| 文档管理 | `POST /api/kb/datasets/{id}/documents` | 批量上传、触发解析 |
| 解析进度 | `GET /api/kb/datasets/{id}/documents` | 轮询解析/切块状态（异步） |
| 切块预览 | `GET .../documents/{doc_id}/chunks` | 查看切块结果 |
| 元数据管理 | `PUT .../documents/{doc_id}` | 标注来源/版本/适用范围/状态 |
| 检索测试 | `POST /api/kb/retrieval` | 输入需求查命中块（调试） |

**实现要点**：
- **API key 只放服务端**，前端永不接触，全部走后端代理。
- **解析异步**：上传后轮询状态，前端做进度条与失败重试。
- **版本管理**：用元数据 `version/status` 字段，旧版标 `status:失效` 后检索自动排除（痛点③）。
- **合规标注**：区分"企业自有/已授权"来源，禁止未授权内容入库。

## 6. 合规保障机制（严禁超范围、来源合规）

| 机制 | 实现 |
|---|---|
| 元数据过滤 | 检索时用 `metadata_condition` 限定适用范围与版本，杜绝越界内容 |
| 提示词强约束 | 生成时明确"只响应招标要求，不额外发挥" |
| 超范围校验 | 生成后检查是否含招标未要求内容，超范围则标记/拦截 |
| 来源引用 | 每个候选强制附引用（来自检索 chunk 元数据），无来源标"待人工补充" |
| 审计日志 | 后端记录上传/检索/生成/选择痕迹，可追溯 |

## 7. 部署架构（需求5）

```
公司机房服务器 / VM
├── Docker 容器
│   ├── app           # FastAPI 后端 + 前端静态资源 + 知识库管理代理
│   ├── ragflow       # RAGFlow（含 DeepDoc/MinerU/Docling 解析）
│   ├── opengauss     # openGauss DataVec（向量 + BM25 + 元数据）
│   ├── minio         # 原始文档对象存储（RAGFlow 依赖）
│   └── model-api     # 模型服务（Qwen3-30B, bge, reranker）
└── 磁盘存储          # 原始文档 + 索引
```

- 用 **Docker Compose** 一键编排，便于复制到不同 VM。
- 模型服务独立容器，可单独扩容（GPU 节点）；MinerU 解析器需 GPU 节点。

---

## 8. 数据流概览

1. 前端上传招标文件 → 后端 → RAGFlow 解析 → 需求清单（存 openGauss）。
2. 需求 → 后端调 RAGFlow 检索（openGauss 向量+BM25）→ 候选响应（附引用）→ 存需求/响应表。
3. 人工挑选 → 更新响应状态 → 组装 → 导出 docx。
4. 定稿 → 经 RAGFlow 回流知识库（解析+切块+索引）。

## 9. 关键决策记录（ADR）

| 决策 | 选择 | 理由 |
|---|---|---|
| 生成模型 | Qwen3-30B 本地 | 能力足够 + 数据不出域 |
| **RAG 引擎** | **RAGFlow（开源）** | 深度文档理解 + 切块/检索/知识库管理开箱即用，避免自研 |
| **向量库** | **openGauss DataVec（≥7.0）** | 国产化信创合规 + HNSW/PQ 索引 + BM25，一个库管向量与元数据 |
| **解析器** | DeepDoc(默认)/MinerU(复杂PDF,需GPU)/Docling(信创无GPU) | 按文档复杂度与机房条件切换 |
| 切块模板 | manual（技术规范书）/ table / naive | 适配招投标高度结构化文档 |
| 检索 | 混合检索 + 重排 + 元数据过滤 | 兼顾语义与专业术语，保障合规 |
| 交付形态 | 人工逐条挑选 | 人在回路，保证质量合规 |
| 知识库管理 | 前端直管 + 后端代理 RAGFlow | 自主掌控体验，API key 不暴露前端 |

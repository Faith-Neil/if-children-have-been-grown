> 文档状态：草稿 v0.3
> 编写日期：2026-09-22（v0.3：产品升级为 AI 驱动智能编辑器，新增图片资产库 + 模型-知识库读写隔离）

## 2. 技术栈选型

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python | 生态成熟，RAG/LLM 工具链丰富 |
| 生成模型 | Qwen3-30B（本地） | 本机部署，能力足够，数据不出域 |
| **RAG 引擎** | **RAGFlow（开源）** | 深度文档理解 + 模板切块 + 混合检索 + 重排 + 知识库管理 |
| Embedding | bge-m3（本地） | 中文好，支持稠密+稀疏向量 |
| 重排 | bge-reranker（本地） | 精排召回结果 |
| **向量库** | **openGauss DataVec（≥7.0）** | 国产化，HNSW/IVF/PQ + BM25，管向量与元数据 |
| 关系库 | openGauss（复用） | 需求/项目/版本/审计日志 |
| **对象存储** | MinIO | 原始文档 + 图片资产库存储 |
| **编辑器前端** | Tiptap/ProseMirror（WYSIWYG） | 所见即所得，支持光标选中、富文本、自定义引用标注 |
| 工作流编排 | LangGraph 或 Dify（仅 workflow 模式） | 确定性工作流，非自主 Agent |
| 后端 | FastAPI | 业务 API + 隔离门 + KB 网关 + 图库服务 |
| 前端框架 | Vue/React | 编辑器 + 知识库管理 + 图库页面 |
| 部署 | Docker + Docker Compose | 一键部署到机房 |

## 3. RAG 管线（由 RAGFlow 承载，只读）

> RAGFlow 负责"解析→切块→向量化→检索→重排→知识库管理"，后端通过其 HTTP API / Python SDK（`ragflow_sdk`）只读对接。

### 3.1 文档解析（解析器多选）
| 解析器 | 适用场景 | 资源 | 结论 |
|---|---|---|---|
| **DeepDoc**（默认） | 普通 PDF/Word，MVP | 低 | 先用它 |
| **MinerU** | 复杂表格/公式/扫描件 | **需 GPU** | 技术规范书复杂时用 |
| **Docling**（IBM） | 信创/敏感/无 GPU | 轻量 | 隔离环境首选 |

- ⚠️ 换解析器需重新解析全库，定好再切。

### 3.2 结构化切块
- 按版面/标题层级切分，保留父级上下文；表格单独成块。
- 技术标建议 `manual` 模板，表格多 `table`，或 `naive` 起步。
- 每块附加元数据（来源/章节/类型/适用范围/版本/状态）。

### 3.3 检索与重排
- 混合检索（稠密 + BM25）+ 元数据过滤（版本/适用范围）+ bge-reranker 精排，取 Top5~8。

## 4. 工作流编排（需求提取 → 生成 → 编辑器）

> 确定性工作流（Workflow），非自主 Agent；仅用 workflow 图模式，不用 ReAct/agent 自主模式。

```
[上传招标包]
   → parse_docs → extract_requirements(提取需求清单)
   → [人工确认需求清单]            ← 检查点①
   → 对每条需求:
        retrieve(只读检索) → generate_candidates(3候选,带引用)
        → [人工逐条选择]           ← 检查点②
   → 写入编辑器草稿区
   → [人工编辑精修 + 插图确认]      ← 检查点③（编辑器内）
   → 合规检查 → 定稿 → 导出 docx
   → [人工审核元数据] → 入库        ← 唯一写入口
```

**人在回路**：需求确认、逐条选择、编辑精修、入库审核四个固定检查点。

## 5. 智能编辑器（AI 驱动，产品核心）

### 5.1 UI 三区布局
```
┌──────────┬────────────────────────┬─────────────┐
│ 需求侧栏   │     文档编辑器(主区)      │  AI 助手面板  │
│ 招标需求   │  WYSIWYG 正文           │  候选卡片     │
│ 条目/状态  │  AI块(引用/状态着色)      │  来源预览     │
│ 覆盖率     │  光标选中→AI操作菜单     │  插图建议     │
└──────────┴────────────────────────┴─────────────┘
```

### 5.2 光标选中 AI 操作（需求3）
| AI 操作 | 说明 | 模式 |
|---|---|---|
| 改写 / 润色 / 扩展 | 局部优化 | 自由型（可不带库） |
| 按招标要求重写 | 贴合某需求 | 内容型（必须带库+引用） |
| 补充技术细节 | 补参数/指标 | 内容型（带库+引用） |
| 插入插图建议 | 查图库推荐 | 图库检索（人工确认插入） |

### 5.3 段状态与合规展示
- 每段状态：`AI生成` / `待确认` / `已确认` / `人工编辑`。
- AI 块带**引用 chip**（可点击跳转来源）；无依据内容**高亮"待补充"**；超范围内容**标红**。
- **只有人工确认过的内容才算定稿**。

## 6. 图片资产库（需求1）

### 6.1 元数据模型
| 字段 | 示例 |
|---|---|
| image_type | 资质证书/设备照片/架构图/系统截图/案例/流程图/Logo |
| title / description | "系统高可用架构图" |
| scope | 适用项目类型 |
| source | 自有 / 已授权 |
| tags | 高可用、双活、国产化适配 |
| version / status | V2 / 有效 |

### 6.2 流程
1. 入库：视觉模型或人工标注自动生成 description + tags（VLM 打标或文本匹配起步）。
2. 撰写：根据"需求条目 + 文档上下文"检索图库（文本/标签匹配，MVP 不必上多模态 embedding）。
3. 建议：AI 在对应位置建议插图 + 候选图 + 图注，**人工确认后插入**。
4. 合规：只建议 `source:自有/已授权` 的图。

## 7. 知识库管理（前端直管 + 后端代理 RAGFlow）

| 前端页面 | 后端端点（代理） | RAGFlow 能力 |
|---|---|---|
| 知识库列表 | `POST/GET /api/kb/datasets` | 创建/列出数据集 |
| 文档管理 | `POST /api/kb/datasets/{id}/documents` | 批量上传、触发解析 |
| 解析进度 | `GET .../documents` | 轮询解析状态（异步） |
| 切块预览 | `GET .../documents/{doc_id}/chunks` | 查看切块 |
| 元数据管理 | `PUT .../documents/{doc_id}` | 标注来源/版本/状态 |
| 检索测试 | `POST /api/kb/retrieval` | 调试 |

**要点**：API key 只放服务端；解析异步需轮询；版本用元数据 `version/status`，旧版标失效后检索自动排除。

## 8. 模型-知识库读写隔离（需求3/4，防污染核心）

**核心思想**：知识库是"只读受控数据源"，模型是"受约束执行者"，中间隔"隔离门"；所有 AI 产出先进草稿区，只有人工审核才能入库。

```
 用户问题/光标选中
      │
      ▼
 ┌──────────────┐   只读检索    ┌─────────────┐
 │ 模型/编辑器    │ ───────────► │ 检索门(Gate) │
 │ (受约束执行者) │ ◄─────────── │             │
 └──────────────┘  返回受限chunks└─────────────┘
      │                          │ 元数据过滤(版本/范围)
      │                          ▼
      │                openGauss 知识库（只读）
      ▼
 ┌──────────────┐
 │ 校验门(输出)   │ ← 超范围/无依据/敏感 检测
 └──────────────┘
      │ 通过
      ▼
 候选响应(带引用) → 草稿区 → 人工确认 → 才可能写入文档
```

### 双数据平面
| 平面 | 内容 | 写权限 |
|---|---|---|
| **权威侧** | 知识库 / 图片库 / 需求库 | 只读（仅入库流程可写） |
| **草稿侧** | 项目草稿 / 会话上下文 / 候选响应 | 可写（不入权威库） |

### 四条隔离原则
1. **上下文白名单**：每次生成只注入本次检索命中的 chunks，不注入整个知识库——模型看不到库外信息，无从"编造有依据"。
2. **只读数据源**：模型经检索 API 只读访问，代码层不提供"从编辑器写库"路径；知识库只有人工审核入库一条写入通道。
3. **无状态调用**：模型调用无状态、不累积学习，投标知识库不被模型"吸收"。
4. **输出校验门**：生成结果过超范围/无依据/敏感检测，不合格拦截。

### 双模式模型调用
| 模式 | 场景 | 知识库 | 引用 | 入库 |
|---|---|---|---|---|
| **内容型** | 生成/重写/补细节 | 强制只读检索 | 强制 | 否 |
| **自由型** | 润色/措辞/解释 | 不带 | 标注"未引用库" | 禁入 |

## 9. 合规保障机制（证据链）

| 机制 | 实现 |
|---|---|
| 引用 chip | 段落级引用来源（文档+章节），可点击跳转 |
| 需求↔段落映射 | 每段对应哪条招标需求，反向可查 |
| 超范围标记 | 生成后比对招标需求原文，越界标红/拦截 |
| 无依据标记 | 无引用内容高亮"待补充"，不得冒充有依据 |
| 状态管理 | 段落状态 AI生成/待确认/已确认，人工确认才定稿 |
| 审计日志 | 上传/检索/生成/选择/编辑全链路可追溯 |

## 10. 部署架构

```
公司机房服务器 / VM
├── Docker 容器
│   ├── app           # FastAPI 后端（业务+隔离门+KB网关+图库服务）
│   ├── web           # AI 编辑器前端（WYSIWYG + 图库 + KB 管理）
│   ├── ragflow       # RAGFlow（解析/切块/检索）
│   ├── opengauss     # openGauss DataVec（权威侧：向量+元数据+审计）
│   ├── minio         # 对象存储（原始文档 + 图片资产库）
│   └── model-api     # 模型服务（Qwen3-30B, bge, reranker）
└── 磁盘存储          # 索引 + 图片资产
```

- Docker Compose 一键编排；模型服务独立可扩容（GPU）；MinerU 解析需 GPU。

## 11. 数据流概览

1. 招标文件 → 解析 → 需求清单（权威侧）。
2. 逐条需求 → 隔离门只读检索 → 生成 3 候选（带引用）→ 草稿区。
3. 人工选择 → 写入编辑器草稿 → 精修 + 插图（人工确认）→ 定稿 → 导出 docx。
4. 定稿 → 人工审核元数据 → 回流知识库（唯一写入口）。

## 12. 关键决策记录（ADR）

| 决策 | 选择 | 理由 |
|---|---|---|
| 生成模型 | Qwen3-30B 本地 | 能力足够 + 数据不出域 |
| RAG 引擎 | RAGFlow（开源） | 深度解析/切块/检索/知识库管理开箱即用 |
| 向量库 | openGauss DataVec（≥7.0） | 国产化信创 + HNSW/PQ + BM25 |
| 解析器 | DeepDoc(默认)/MinerU(复杂PDF)/Docling(信创) | 按文档复杂度与机房条件切换 |
| 交付形态 | **AI 智能编辑器**（WYSIWYG + 光标选中 AI 操作） | 保留人工编辑，AI 作为助手 |
| 图库 | 图片资产库 + 元数据，AI 建议、人工插入 | 结构化复用企业图片资产 |
| **读写隔离** | **双数据平面 + 隔离门** | 知识库只读、防污染、合规可审计 |
| 模型调用 | 内容型(强制检索) / 自由型(不检索禁入库) | 限制模型作用域，保护知识库 |
| 合规 | 证据链（引用/映射/状态/审计） | 可追溯、超范围可拦截 |

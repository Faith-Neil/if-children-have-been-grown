# 智能投标系统前端 ROADMAP

## 1. Roadmap 目标

以“先跑通投标主流程，再增强协作和效率”为原则。

第一阶段不是追求页面数量，而是确保以下闭环完整：

```text
项目创建
  ↓
招标文件解析
  ↓
响应矩阵
  ↓
项目事实
  ↓
写作方案确认
  ↓
章节生成
  ↓
编辑台
  ↓
检查
  ↓
导出
```

---

# 2. Phase 0：基础框架

目标：建立稳定前端基础。

范围：

- 登录
- 权限
- 全局 Shell
- 项目 Shell
- 路由
- 基础组件库
- API 封装
- 全局错误处理
- 基础审计埋点
- 长任务状态组件

完成标准：

- 用户可以登录
- 不同角色看到正确导航
- 项目级页面可稳定切换
- 长任务状态可统一展示

---

# 3. Phase 1：项目主流程

优先级：P0

## 3.1 项目管理

实现：

- 项目列表
- 项目概览
- 技术标 / 商务标独立状态
- 项目截止提醒
- 项目风险概览

## 3.2 招标文件

实现：

- 文件上传
- 解析状态
- 解析结果
- 原文查看
- 页码定位

## 3.3 响应矩阵

实现：

- 条款
- 评分项
- 得分要点
- 分册归属
- 响应章节
- 证明材料
- 偏离
- 覆盖状态

## 3.4 项目事实

实现：

- 项目事实查看 / 编辑
- 招标要求值
- 响应值
- 冲突提醒
- 确认状态

完成标准：

> 项目负责人能够从招标文件一直走到可确认的响应规划。

---

# 4. Phase 2：章节生成闭环

优先级：P0

实现：

- 章节树
- 章节状态
- 写作方案确认
- 生成任务
- 生成进度 Timeline
- 多轮版本
- 检查问题
- 自动修正结果
- 转人工处理

完成标准：

> 用户可以从一个未生成章节完整走到“已完成”或“待人工处理”。

---

# 5. Phase 3：编辑台

优先级：最高 P0

这是整个 MVP 最核心前端模块。

## 5.1 编辑器

实现：

- 长文编辑
- 标题 / 列表 / 表格
- 段落定位
- 自动保存
- Undo / Redo
- 只读模式

## 5.2 来源

实现：

- 段落来源标签
- 来源抽屉
- 招标原文
- 项目事实
- 企业资料

## 5.3 AI 助手

实现：

- 普通问答
- 选区修改
- 3 个默认修改建议
- 知识库开关
- 来源引用
- 替换 / 插入
- Diff 确认

## 5.4 版本

实现：

- 版本列表
- 版本比较
- 版本回退

## 5.5 编辑锁

实现：

- 章节级锁
- 心跳
- 只读提示
- 强制接管
- 接管原因

完成标准：

> 编写人员能够稳定完成长文修改，任何 AI 修改都可预览、确认、回退和追溯。

# 13. 验收 Gate

每个阶段上线前必须满足：

### Gate A：安全

- 不丢草稿
- 不静默覆盖正文
- 不绕过权限
- 不绕过编辑锁

### Gate B：可追溯

- 修改有版本
- AI 写入有来源
- 问题可定位
- 导出可追踪

### Gate C：主链路

- 不依赖后台人工改库
- 不需要研发手工介入
- 用户可自行完成当前阶段任务

---

# 14. Roadmap 原则

1. 先做完整主链路，不先堆高级 AI 功能。
2. 编辑台优先级高于统计分析。
3. 来源和版本优先级高于“看起来聪明”的生成能力。
4. 项目负责人视角与编写人员视角必须同时成立。
5. 企业资料库先保证可用和可控，再做高级知识运营。

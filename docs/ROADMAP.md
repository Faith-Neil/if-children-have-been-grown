## 2. 分期计划（8 周 MVP 路径）

### M1 · RAG 最小闭环（第 1–2 周）
**目标**：先把"知识库 → 检索 → 生成"这条最核心的链路跑通，验证 RAG 可行性。

- [ ] 环境搭建：机房部署 Qwen3-30B、bge-m3、bge-reranker（Ollama 或 vLLM）
- [ ] 部署 RAGFlow（开源 RAG 引擎，使用其自带文档/向量引擎），业务关系库使用 MySQL
- [ ] 用少量历史标书在 RAGFlow 中建知识库、做结构化切块（manual/naive 模板起步）
- [ ] 后端封装"提问 → RAGFlow 检索 → 重排 → Qwen3 生成回答（带引用）"的最小脚本
- **验收**：对几个典型需求能检索出相关内容并生成带引用的回答

### M2 · 工作流编排 + 需求提取（第 3–4 周）
**目标**：把单点能力串成"招标文件→需求清单→逐条生成"的工作流。

- [ ] 招标文件解析（docx/pdf，标题层级 + 表格；按需选 DeepDoc/MinerU/Docling 解析器）
- [ ] 需求提取模块（LLM 从招标文件提取需求条目清单）
- [ ] 用 LangGraph（或 Dify）编排工作流，含"需求确认"人工暂停点
- **验收**：上传一份真实招标包，能产出可用的需求清单并逐条生成候选

### M3 · AI 智能编辑器（第 5 周）
**目标**：实现"逐条多候选选择 + WYSIWYG 编辑 + 光标选中 AI 操作"（产品核心）。

- [ ] FastAPI 后端 API（编辑器服务 + 隔离门骨架）
- [ ] WYSIWYG 编辑器（Tiptap/ProseMirror）：需求侧栏 + 主编辑区 + AI 助手面板
- [ ] 光标选中 AI 操作：改写/润色/重写/补充细节/插图建议
- [ ] 段状态管理（AI生成/待确认/已确认）+ 引用 chip
- **验收**：逐条选候选后进入编辑器，能光标选中提问并精修，导出 docx

### M4 · 检索质量优化（第 6 周）
**目标**：针对痛点①，把检索质量做扎实。

- [ ] 解析器选型与切块模板调优（DeepDoc 默认 / MinerU 复杂PDF / Docling 信创，manual/table/naive）
- [ ] 混合检索（稠密+BM25）+ 重排联调，元数据过滤（来源/版本）
- [ ] 检索质量评测（召回率/命中率），迭代优化
- **验收**：典型需求检索命中率达标

### M5 · 知识库 + 图片库 + 读写隔离（第 7 周）
**目标**：解决痛点②③，并落实"知识库只读、防污染"。

- [ ] 知识库管理代理（后端封装 RAGFlow 上传/解析/切块/检索 API）
- [ ] 前端知识库管理页：上传、解析进度、切块预览、元数据标注
- [ ] 图片资产库：元数据模型 + 上传打标 + AI 建议插图
- [ ] 读写隔离落地：双数据平面 + 检索门/校验门 + 唯一入库闸门
- [ ] 版本管理与失效内容处理；增量索引 + 内容回流
- **验收**：前端能管理知识库与图库；新增可增量入库；旧版本不干扰检索；编辑器无写库路径

### M6 · 生产化部署（第 8 周）
**目标**：满足需求 5，交付可上线系统。

- [ ] Docker Compose 打包（后端/前端/ragflow/mysql/minio/模型服务）
- [ ] 部署到公司服务器 / VM 并验证
- [ ] 合规保障与读写隔离核对（不超范围、来源可追溯、知识库只读）
- [ ] PRD / ARCHITECTURE / ROADMAP 三件套定稿
- **验收**：系统在公司机房一键启动可用，试点一个真实项目

## 3. 任务优先级（P0/P1/P2）

| 优先级 | 任务 |
|---|---|
| **P0（必须）** | 结构化切块、混合检索+重排、需求提取、多候选生成、**AI 智能编辑器**、来源引用、**读写隔离（知识库只读）**、Docker 部署 |
| **P1（重要）** | 元数据过滤、版本管理、增量索引、内容回流、超范围校验、**图片资产库** |
| **P2（增强）** | 多用户权限、项目隔离、审计日志、检索质量评测工具 |

## 4. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 切块质量不佳 | 检索不准、生成差 | 用结构化切块 + 混合检索 + 重排，M4 专项调优并评测 |
| 需求提取漏项/错项 | 响应不完整 | 提取后人工确认环节兜底；用真实招标文件校准 |
| 生成超范围 | 合规风险 | 提示词强约束 + 超范围校验拦截 + 无来源内容标"待补充" |
| 知识库初始质量 | 检索结果差 | 入库前清洗、去重、标注元数据；试点项目校验 |
| 多候选同质化 | 人工挑选意义弱 | 生成时强制差异化（详略/角度/表述） |

---

## 5. 验收基线（与 PRD 对应）

- 需求提取：能从典型招标文件提取主要需求条目，人工可修正。
- 检索命中：对典型需求召回相关历史标书内容。
- 多候选：每条需求生成 3 个候选，均带来源引用。
- 超范围率：明显超范围内容占比低，可被校验拦截。
- 组装导出：按章节组装并导出 docx。
- 部署：系统在公司机房 / VM 一键启动可用。

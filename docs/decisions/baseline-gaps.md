## 收敛顺序与完成条件

1. 先完成 PR #1 的文档层级与范围评审，明确系统方案和前端实施视图分别负责什么。
2. 补技术方案与有效设计规范，逐条处理 BG-02～BG-09 的业务和技术边界。
3. 明确一期页面、公司隔离、答案卡、解析确认门、敏感导出及默认任务卡依赖。
4. 形成可评审的 API、任务状态和编辑器数据契约，再开始正式应用接入。
5. 更新前端需求、架构与路线图，并为每个关闭差异记录决定、日期、依据和验收方式。

只有差异有明确结论、实施视图已更新、契约与验收项一致后，才将对应事项标为已对齐。当前全部 BG 项为待评审；目录归位可以独立完成。

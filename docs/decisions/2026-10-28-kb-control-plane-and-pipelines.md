为什么有这个文件：记录公司知识库管控接口、ICG 摄入流程设计，以及“招标文件解析与按要点撰写是否用 RAG”的决定。

它解决什么问题：让后续开发知道每类知识怎么入库、谁能改什么、哪些环节故意不用向量检索，以及理由。

# 知识库管控、ICG 摄入流程与招标文件解析的技术决定（2026-10-28）

关联：[ISSUE-043](../../issues/ISSUE-043.md)、任务 AI-KB-CONTROL-PLANE、AI-KB-RAG-EVAL；依据 PRD v1.8 原则 1（零虚构）、§5.2（招标解析）、§5.7（证据挂接）、B5/B6（自建 RAGFlow、数据不出内网）。实测对象 RAGFlow v1.0.0-rc2。

## 1. 知识分四类，各用一个数据集和一条流程

| 类别 | 数据集 | 内容来源 | ICG 流程 | 检索用途 |
|---|---|---|---|---|
| library | `{公司}::icg-library` | 资料库已确认未过期资料、已发布片段（系统自动同步） | 结构化资料：按 `#/##` 标题切块，每块带资料名称；LLM 生成 3 条“招标式问法”+5 个关键词 | 写作候选；资料可由人挂为 [证]，片段写 [片:id] |
| history | `{公司}::icg-history` | 管理员上传的历史投标/响应文件原件 | 历史投标文件：DeepDOC 版面解析，按投标文件编号体系（第X章 → 一、 → （一） → 1. → 1.1）切块并保留章节路径；表格单独成块；问法×2、关键词×5；抽取项目名称、采购人、行业、投标日期、项目类型 | 只作参考，永远不能挂为证据 |
| certificate | `{公司}::icg-certificate` | 证书、合同等扫描件/照片 | 证书附件：OCR，整页一块（不拆证书）；抽取证书名称、编号、发证机构、持有人、有效期、范围 | 不进写作检索；抽取结果一键生成“待核验”资料，由资料管理员核对原件后确认 |
| tender | 按项目（尚未接入） | 本项目招标文件 | 招标文件：DeepDOC，按章节层级切块、保留页码位置，不做 LLM 改写 | 见第 4 节 |

设计要点：

- **问法生成**解决招投标最大的语义差：招标写“投标人须具备信息安全管理体系认证”，资料写“ISO/IEC 27001 证书编号…”。提示词要求只依据片段、不得编造。
- **按章节切块并带章节路径**：历史投标文件动辄数百页，固定长度切块会把“第五章 技术方案 › 三、运维服务方案”切散，召回后无法判断出处。
- 流程按公司部署，标题 `icg::{公司}::{流程}::v{版本}`；组件 id 由流程键派生、可复现；DSL 同时写后端参数与画布表单，避免有人在 RAGFlow 界面打开保存后覆盖参数。
- 公司可调项：抽取模型、切块长度、问法/关键词数量、追加标题规则（如“附件 1”）。改动后重新部署，数据集重新绑定并标记“需重新解析”。
- RAGFlow 不支持画布接口或部署失败时，退回内置 general 解析器并在界面提示，不阻断同步。

## 2. 管控接口（/api/v1/kb-admin）与授权

| 能力 | 接口 | 读 | 写 |
|---|---|---|---|
| 总览、模型列表、设置 | `overview`、`models`、`settings`（If-Match） | 公司管理员、资料管理员、项目负责人 | 公司管理员、资料管理员 |
| 摄入流程 | `pipelines`、`pipelines/{key}/dsl`、`pipelines/deploy` | 同上 | 同上 |
| 数据集 | `datasets`、`/{kind}/ensure|reparse|rebuild`、`/{kind}/metadata` | 同上 | 同上 |
| 删除整类数据集 | `/{kind}/delete`（输入全名确认） | — | 仅公司管理员 |
| 文档 | 列表、上传原件（base64，≤50MB）、启停、改元数据、重解析、停止、删除 | 同上 | 公司管理员、资料管理员 |
| 分块 | 列表、修改关键词/问题/启停；原件分块可改正文 | 同上 | 同上 |
| 证书 → 资料草稿 | `certificates/{doc}/library-draft` | — | 同上 |
| 检索试查 | `retrieval-test`（可临时覆盖阈值/权重/重排） | 同上 | — |
| 审计 | `audit`（最近 500 条） | 同上 | — |

- RAGFlow 连接地址与密钥（`PUT /api/v1/ragflow-config`）改为只有公司管理员可改：它决定公司资料流向哪里（B5）。此前任何登录用户都能改，属安全缺口。
- 资料与片段文档由系统维护：不能在这里删除或改正文，只能调关键词/问题或停用分块；要下架请在资料库撤销确认。
- 只操作本公司索引登记的数据集与文档；文档 id 不属于本公司一律 404。
- 更换嵌入模型会把所有数据集标为“需要重建”；重建会新建数据集、从旧数据集下载原件迁移、重新同步资料，再删除旧数据集，原件取不回时整体停止，不会丢数据。
- 2026-10-28 用户决定去掉演示环境后，三角色兼容已删除，资料管理员、公司管理员均可登录界面；界面按角色只读/可写。

## 3. 检索保持“只认索引、实时复核”

历史原件命中按 `file:` 条目复核（未删除、已启用、本公司），且 `reference_only=true`。多个数据集一起检索的前提是同一嵌入模型，由设置统一管理。

## 4. 招标文件解析与按要点撰写：是否用 RAG / 向量库

结论：**条款抽取不用 RAG；写作时取用公司知识要用 RAG；招标原文的“版面理解”值得借 RAGFlow，但向量检索只作辅助。**

| 环节 | 是否用向量检索 | 理由 |
|---|---|---|
| 招标文件 → 条款、★/▲ 实质性要求、评分项、废标项、格式要求 | 否，按章节全量顺序处理 | 必须穷尽：漏一条★就可能废标。top-k 召回天然会漏，且无法证明“没有漏”。现有做法（按页抽取、引用原文页码与原句校验 `_source_valid`、★/废标兜底扫描 T111）是对的，应保持。 |
| 招标文件版面解析（扫描件、表格、跨页表） | 借用 RAGFlow DeepDOC（tender 流程） | 当前本地解析器对扫描 PDF 与复杂表格能力弱；DeepDOC 的版面/表格识别比自研划算。只用它的解析与位置信息，抽取仍由本系统逐章完成。 |
| 撰写章节时取本项目招标原文（技术参数、评分细则、格式） | 主要靠响应矩阵映射；辅以项目内检索 | 矩阵已把条款挂到章节，是确定性的。长篇技术规格中“与本章相关的其他段落”可用项目内检索补充，按项目建临时数据集，项目归档后删除。 |
| 撰写时取公司资质、业绩、人员、方案片段、历史标书 | 是（本次已接通的公司知识库） | 资料量大、表述与招标要求不一致，正是 RAG 的用途；命中只是候选，[证] 仍须人挂接。 |
| 合规核对（正文是否响应每条★、是否引用了过期证据） | 否 | 规则 + 结构化数据（矩阵、证据有效期）可确定判断，不应交给相似度。 |

后续任务（未开工）：tender 流程接入招标解析（按项目数据集、读取分块与位置构建章节树，再逐章抽取），以及编辑台“查招标原文”。

## 5. 未完成与风险

- 真实 RAGFlow 上的质量评测仍未完成：租户默认嵌入模型（Jiekou.AI）的域名在用户网络里被解析到 198.18.x（代理假 IP），被 RAGFlow 的内网地址保护拦截；Gemini 免费额度当日用尽。需要用户提供可用的嵌入模型（建议直接部署内网 bge-m3，与生产一致）。
- 流程的 LLM 抽取会显著增加解析耗时与成本（每块一次调用）；生产需用内网 Qwen，并按评测结果决定问法数量。
- ICG 流程尚未在真实 RAGFlow 上跑通一次完整解析（部署与绑定已在真实实例验证；解析被嵌入模型问题阻塞）。

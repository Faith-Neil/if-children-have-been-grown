# PRD v1.8 实施澄清（Wave 11）

- 日期：2026-10-28；决定人：项目经理（用户 2026-10-28 授权本会话全权担任 PM）
- 关联：[ISSUE-039](../../issues/ISSUE-039.md)、[ISSUE-040](../../issues/ISSUE-040.md)
- 状态：生效（实施口径）；建议在 PRD v1.9 中吸收

| 编号 | PRD 位置 | 原文问题 | 澄清（现行实现） | 理由 |
|---|---|---|---|---|
| A1 | §5.7.4 第 5 条第 3 项 | 只要求模型修正“过 5.7.3 规则 3 和规则 7”，没有可执行的判定 | 模型定位修正的结果出现以下任一情况即拒绝采用，改用确定性修正：带入原段落没有的数字；带入原段落没有的证据或片段引用；产生新的直接转人工缺陷；包含对话残留或换行 | “不编造”必须可机器判定；数字与引用是最常见的编造载体 |
| A2 | §2.3“定稿前交叉复核确认”、§5.8.5 | 没有定义“该分册的编写人” | 编写人＝本分册负责人、本分册任一章节的被分配人、提交过本分册非空正文版本的人（章节循环的系统修正版本不计）。复核人须是本项目可编辑成员且不属于编写人 | 交叉复核的意义是“非作者复看”，提交过正文即是作者 |
| A3 | §5.8.5 | 只说“确认、留痕”，没说复核与正文变化的关系 | 复核结论为“通过 / 退回修改”，退回必须写原因；通过时绑定本分册各章节版本与内容指纹，之后正文有任何改动，复核即失效，须重新复核才能定稿；定稿记录同样保存章节快照 | 防止复核后再改正文绕过复核 |
| A4 | §4.3 规则 1、§5.8.5 | 只规定“已导出后修改章节”使导出过期 | 解锁分册本身（即使正文未改）即让本项目已有检查与导出过期，交叉复核作废 | 解锁是明确的“定稿失效”边界，避免拿解锁前的检查继续导出 |
| A5 | §5.2.4 第④步 | “已被某条星号或废标条目覆盖”没有判定口径 | 覆盖＝存在未被排除的星号/废标条目，且与命中块同文件同页、原文互相包含，或条目原文包含命中原文；星号/废标判定与合规检查、定稿门禁用同一函数（★、标星、废标、否决、类别或重要性为星号/废标） | 三处判定一致，避免解析确认放行而检查拦截 |
| A6 | §5.2.4 规则 2 | “新增为条目”在已有同一原文的普通条目时会产生重复 | 已有同一来源（文件、页、原文）的条目时改为升级该条目的类别与重要性并退回待确认；否则新建 | 一条原文只保留一个条目，矩阵不重复 |
| A7 | §5.7.5 规则 1、§5.8.5 | 要求分册内章节均为“已完成/人工已处理”，未说明从未跑过章节循环、由人直接编写的章节 | 有正式正文、从未运行章节循环的章节按“人工已处理”对待；运行过循环的章节，只要还有待人工问题就不能定稿 | 一期允许人工直接撰写；不因缺少循环记录卡死定稿 |
| A8 | §5.8.1 R15 | 只列【待补】 | 【待补】【待完善】【待确认】【占位】及 TODO/TBD/XXX 等占位都按 R15 处理，没有对应已确认事实时一律转人工，不允许改写成任何承诺文字 | 模型常用英文占位，同样是未补齐的事实 |

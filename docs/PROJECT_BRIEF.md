## 项目在解决什么

目标是帮助企业把招标要求、公司资料与承诺组织成有来源、可检查的投标文档：上传招标包 → 解析并人工确认 → 响应矩阵与事实/SLA → 确认写作方案 → 章节生成/修正 → 人工编辑 → 检查/定稿 → 分册Word导出。响应矩阵是“每项要求由哪里响应、用什么证据”的对照表。

一期技术、商务两册已由用户确认；最终合标、页码、签章与平台递交由人在系统外完成。合作分支技术标草稿与此范围的具体差异继续评审；详见 [一期交付建议](decisions/phase-one-scope.md)。

## 接手后最先关注的六件事

| 优先事项 | 不解决会怎样 | 下一步产物 |
|---|---|---|
| 完整示例范围 | 主流程能点通，却漏掉其余页面、规则和分册定稿 | 按覆盖清单继续拆任务，每项有独立交付证据 |
| 漏抽与关键引用 | 已抽出的条目都正确，也可能漏掉关键否决要求 | 原文独立标注样本、漏抽复核和附件引用门禁 |
| 事实/证据变更 | 旧检查可能不再覆盖新输入 | 已接通输入变动使检查和旧导出失效，继续补齐完整依赖与验收 |
| 编辑和任务完整性 | 纯文本编辑与同步任务不够支撑原示例的复杂编标流程 | 段落、来源、变量、选区助手、恢复与任务进度能力 |
| 公司权限、敏感字段及SLA | 基础公司隔离不等于全部角色和承诺边界已经齐全 | 正式身份、字段权限、敏感资料治理与服务响应承诺核对 |
| Word及交付 | 可下载文件不等于能直接递交 | 正式模板、目录、附件、页面渲染、定稿和递交权限验收 |

审查结论是：方向能覆盖主要编标场景，主流程已经有本地验证证据，但仍不能据此宣布完整产品或正式投标交付已完成。缺口分为来源差异、待细化设计和待实现功能，逐项关联任务。SLA指服务响应承诺，例如“故障多久响应”，需要同时核对招标要求和企业实际能力。

目录采用一个模块化业务核心，页面通过接口使用同一份数据。适配器就是连接外部服务的转换层，让模型、解析器或存储可以更换而不重写页面流程。当前解析和生成仍同步执行；后台worker是专门处理长任务的进程，尚未建立可恢复任务系统。独立服务、集群安装和离线包随实际环境与验收需要产生。

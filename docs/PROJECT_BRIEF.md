## 项目在解决什么

目标是帮助企业把招标要求、公司资料与承诺组织成有来源、可检查的投标文档：上传招标包 → 解析并人工确认 → 响应矩阵与事实/SLA → 确认写作方案 → 章节生成/修正 → 人工编辑 → 检查/定稿 → 分册Word导出。响应矩阵是“每项要求由哪里响应、用什么证据”的对照表。

一期技术、商务两册已由用户确认；最终合标、页码、签章与平台递交由人在系统外完成。合作分支技术标草稿与此范围的具体差异继续评审；详见 [一期交付建议](decisions/phase-one-scope.md)。

本次补上了“公司模板与实际能力 → 登记招标原文和要求 → 比较我方承诺 → 负责人处理风险 → 到事实表逐条确认 → 编辑台插入变量 → 检查和内部Word输出”的数值链路。服务承诺（SLA）就是“发生故障后多快响应、多久恢复”等承诺。工作日与自然日等无法可靠换算的情况交人判断；不满足招标的值不能通过批准变成满足；改了来源、模板或数字，原确认和旧下载会失效。实际输出含两册内部稿和单独的内部承诺函表格，本轮验证与限制见[数值服务承诺阶段验证](testing/2026-10-10-sla.md)。

这仍是部分实现：故障等级、服务时段的完整比较、模板外承诺类事实、完整业务规则和正式Word版式尚未完成。章节生成器和整章修改建议已实际接收本章选定事实及全部必备服务承诺，同时保存取值、变量键和来源；模型仍为替身。人可插入变量，检查和导出读取同一个已确认取值。完整事实语义和逐段来源仍待实现。纯文本变量也不等于完整的结构化编辑器。完整范围保留在[ICG覆盖清单](testing/icg-coverage.md)，没有完整参考规则因本轮子集而被算作完成。

写作输入此前通过168项后台、22项前端及两册内容核对，见[写作验收](testing/2026-10-10-writing-input.md)。本次新增项目成员、分册及章节分工、逐章独立确认和旧页面防覆盖，210项后台、36项前端、实际多人页面与文件通过，见[成员验收](testing/2026-10-10-project-assignments.md)。项目负责人管全部，分册负责人管本册，编写人管自己的章节；交接保留每人的稿子，离开分工后旧权限立即停止写入。逐段来源和正式Word版式仍未完成，人工取值是否符合所有原文含义仍不能自动判断。

模型替身相当于一个暂时代替真实AI的固定回答器，便于先验证流程。内存存储相当于只存在本次运行中的账本，重启就清空。两者有明确替换接口；本轮按要求预留，不把接入真实模型、数据库当作推进页面的前提。上传文件里的文字提取是真实执行的，但不等于智能理解、完整漏抽检查或扫描件识别已经完成。

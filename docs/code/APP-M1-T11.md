# APP-M1-T11：承诺变量、检查与承诺函代码解释

日期2026-10-10，版本reference-sla-1，关联[ISSUE-007](../../issues/ISSUE-007.md)与[任务卡](../tasks/APP-M1.md#app-m1-t11)。

## 入口与数据流

编辑台可插入完整服务变量和模板单位。后台将项目单位换算成模板单位，固定后缀不一致时拒绝；明确指标名称的手写数字也参加检查。技术、商务内部稿和实际承诺函表格采用同一个已确认值；修改输入使旧文件拒绝下载。

实际位置：EditorPage.tsx / sla-form.ts；sla.py 的 resolve_variables / sla_issues / commitment；workflow.py 的项目检查与两册输出；adapters.py 的 Word 表格；domain.py 的旧出口保护。 前端位于frontend/web/src，后台位于backend/bid-core/icg_demo。

页面先读取当前工作区或公司资料版本，发送本次版本和重复请求标记。后台核对公司、角色、来源与输入，在一个事务中保存状态；失败会回滚，页面保留填写内容。事务相当于“这一笔操作全部完成后才记到账本”，避免只改了一半。

模板、项目承诺和派生事实通过同一份数据关联。项目输入摘要是参与本次核对资料的指纹；它把模板、承诺、当前核对和已提交正文纳入，旧候选、检查或下载因此不能沿用。审计保留实际操作者、理由和旧/新值。

## 关键判断与失败保护

服务值必须有限、非负并符合整数/小数/文字类型；空值不自动变零，布尔值不能冒充数字。分钟、小时、自然日可明确换算；工作日、月或不同周期频次不强行等同。承诺劣于招标不能由人工批准变成满足；能力未知、单位不可证明、原文未量化或额外承诺需要负责人留依据。

模板和来源变化使核对失效，事实值只读。变量输出前核对当前事实确认，遇到未知、未闭合或单位冲突变量拒绝；旧单章检查、导出和下载也不能绕过项目流程。只有旧的独立单章演示仍保留其入口。

## 入口与行为

编辑权绑定账号与登录会话，定期续期。草稿另存、正文提交产生新版本。恢复核对后台版本与草稿sequence后先持久保存草稿，再替换页面文字，失败不假称成功。ModelProvider仅返回建议，两个入口均核对敏感模型路由；input_snapshot.py让相关资料变化使旧候选失效。

源码位置：EditorPage.tsx、RecoveryReview.tsx、editor-recovery.ts；domain.py、input_snapshot.py、workflow.py。前端位于frontend/web/src，后台位于backend/bid-core/icg_demo；启动器在业务核心目录。

## 本次追加：正文服务承诺变量

EditorPage.tsx从项目矩阵列出已有效确认的SLA变量，编辑者持有当前编辑权时可在正文光标或选区插入完整标记，例如`{{sla:P1.response}}`。sla-form.ts只替换所选内容并核对后面的单位；旧单位冲突时要求将旧单位一并选中，避免误改正文或把小时写成分钟。插入后仍须保存草稿、提交正式正文，不自动采纳或输出。

sla.py在检查和导出时读取矩阵的当前已确认值，换算到模板单位；未知、未确认、无法换算或冲突单位的变量拒绝输出。明确匹配“指标名称＋数字＋单位”的手写数值不一致时定位到章节，不能宣称覆盖所有自然语言表达。input_snapshot.py使来源、模板或取值变化使旧候选、检查与下载失效。

生成候选的workflow.py当前只组织本章条款、响应和证据；旧建议入口domain.py只读取正文。两处尚未自动注入SLA派生事实及变量键，当前准确链路是人工插入变量，再由检查和输出统一取值。完整故障等级、服务时段比较、全文规则和正式Word版式仍未完成，证据与限制见[本次阶段验证](../testing/2026-10-10-sla.md)。

当前Repository为内存实现，进程重启清空；模型为演示替身。替换数据库要保持原子提交与失败回滚，替换模型要声明是否本地、核对公司和敏感项目路由；只留接口不表示真实服务已接入。

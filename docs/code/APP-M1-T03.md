# APP-M1-T03：实际代码说明

日期2026-10-10。关联[ISSUE-007](../../issues/ISSUE-007.md)和[阶段交付](../delivery/APP-M1-T03.md)。保留reference-1主流程阶段说明，本次追加reference-sla-1数值服务承诺；任务仍in-progress。

## 入口与行为

矩阵PATCH必须匹配项目版本；后台核对章节分册、公司资料可用状态与日期。资料修改使用公司资料版本，实质变化进入待确认，同次再次确认须理由。事实冲突的已选值改动后重新打开，不沿用旧选择。

源码位置：ProjectPages.tsx MatrixPage/FactsPage；SupportPages.tsx LibraryPage；workflow.py。前端位于frontend/web/src，后台位于backend/bid-core/icg_demo；启动器在业务核心目录。

## 验证与后续

[实际验证](../testing/2026-10-10-icg-reference.md)保留网络、页面与输出证据。公司隔离、只读拒绝、旧版本冲突和重复请求保护由后台执行，不能只靠界面按钮。

reference-1阶段的SLA仅有筛选入口，三列能力比较当时未齐。该历史状态由以下本次数值实现补充；评分/偏离、完整分流、真实人员和附件字段仍未齐，解析器尚不自动完成全部分类与漏抽核对。

## 本次追加：服务承诺与引用型事实

SlaPages.tsx在响应矩阵内提供服务承诺二级切换，显示招标要求、项目承诺和公司能力极限。sla.py根据单位和优劣方向计算七类判定；不满足招标的值不能批准，超出能力或需人工判断的项必须负责人留下核对依据。公司模板与项目取值分开保存，项目改值不修改公司能力。完整故障等级及服务时段比较仍未实现。

ProjectPages.tsx的FactsPage显示由矩阵实时派生的事实，取值只读；负责人逐项确认时调用同一个项目接口。后台拒绝直接改值或忽略必备承诺，数值、来源或模板变化使确认需复核，并使相关候选、检查和旧下载失效。input_snapshot.py把服务承诺项目值、核对记录及公司模板纳入统一输入摘要，即用于判断相关资料是否已经变化的标记。

本次数值链路由APP-M1-T09～T11细分实现，证据见[阶段验证](../testing/2026-10-10-sla.md)。生成器尚未自动把SLA派生事实及变量键加入模型输入；事实表可读并不代表完整事实注入已经实现。当前人在编辑台插入明确变量，再由检查与输出读取已确认取值；模板外承诺事实、完整R09/R10/R30和正式Word版式继续验收。

当前Repository为内存实现，进程重启清空；模型为演示替身。替换数据库要保持原子提交与失败回滚，替换模型要声明是否本地、核对公司和敏感项目路由；只留接口不表示真实服务已接入。

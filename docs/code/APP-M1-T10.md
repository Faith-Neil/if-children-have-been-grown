# APP-M1-T10：三方对照、判断与事实引用代码解释

日期2026-10-10，版本reference-sla-1，关联[ISSUE-007](../../issues/ISSUE-007.md)与[任务卡](../tasks/APP-M1.md#app-m1-t10)。

## 入口与数据流

把招标原要求、项目承诺和公司能力放在同一矩阵。后台计算七类结果，按招标取值不突破公司能力；风险核对仅对当前输入有效。事实表直接引用矩阵值，不可另改；变化后需负责人重新确认。

实际位置：SlaPages.tsx 的 SlaMatrixPage；ProjectPages.tsx 的 FactsPage / OverviewPage；sla.py 的 public_sla / patch_value / review / confirm_fact；App.tsx 的当前待确认摘要。 前端位于frontend/web/src，后台位于backend/bid-core/icg_demo。

页面先读取当前工作区或公司资料版本，发送本次版本和重复请求标记。后台核对公司、角色、来源与输入，在一个事务中保存状态；失败会回滚，页面保留填写内容。事务相当于“这一笔操作全部完成后才记到账本”，避免只改了一半。

模板、项目承诺和派生事实通过同一份数据关联。项目输入摘要是参与本次核对资料的指纹；它把模板、承诺、当前核对和已提交正文纳入，旧候选、检查或下载因此不能沿用。审计保留实际操作者、理由和旧/新值。

## 关键判断与失败保护

服务值必须有限、非负并符合整数/小数/文字类型；空值不自动变零，布尔值不能冒充数字。分钟、小时、自然日可明确换算；工作日、月或不同周期频次不强行等同。承诺劣于招标不能由人工批准变成满足；能力未知、单位不可证明、原文未量化或额外承诺需要负责人留依据。

模板和来源变化使核对失效，事实值只读。变量输出前核对当前事实确认，遇到未知、未闭合或单位冲突变量拒绝；旧单章检查、导出和下载也不能绕过项目流程。只有旧的独立单章演示仍保留其入口。

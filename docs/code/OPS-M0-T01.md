# OPS-M0-T01：工作区同步代码解释

日期：2026-10-09。关联：[ISSUE-004](../../issues/ISSUE-004.md)、[任务](../tasks/OPS-M0.md#ops-m0-t01)、[交付](../delivery/OPS-M0-T01.md)。

## 入口与数据流

`Start-WorkspaceSync.ps1` 读取工作区外配置，展开本机路径，检查配置/令牌/runtime不在仓库内。用Windows当前用户解密DPAPI文件，在内存给Node子进程传 `WORKSPACE_SYNC_TOKEN`；创建子进程后清除启动环境副本并释放BSTR。实际配置不包含明文令牌。

`sync.cjs` 导出 `WorkspaceSync`，`--run`持续调用tick，`--once`执行一次。配置固定分支与无凭据GitHub URL；测试明确开启本地bare remote模式。单实例nonce/PID锁在工作区外，stop文件请求有序退出。状态/日志仅写固定原因、计数与PID，不保存文件正文、Git原始输出或认证头。

每个tick核对：Git根、正在进行的Git操作、当前分支、拉取/推送URL、人的暂存和链接/gitlink。按30秒周期fetch并判断ahead/behind；双方分叉、远端领先且本地有变化时暂停。只有本地干净且能快进时pull ff-only。

本地候选由Git status产生，因此尊重.gitignore。逐层检查链接/嵌套Git、合同根、凭据文件名、大文件和完整密钥格式；文件内容/mtime哈希稳定10秒后再次核对索引与候选，暂存明确候选并用自动快照身份提交。稳定期存工作区外，可跨once保留。人工已有提交也在推送前扫描所有出站提交中新增/修改的blob，防止“先提交凭据、再删除”绕过历史检查。

Git使用参数数组，不使用shell解释；网络认证放该Git子进程的临时环境配置并关闭交互凭据保存，非网络Git不会获得令牌变量。Git trace环境被关闭。网络失败保留本地提交并5～60秒退避；拒绝推送后重新fetch，绝不强推、reset或自动合并。

## 治理检查的工作区边界

`check-project-governance.cjs` 新增根来源排除：ICG历史资料不套用当前活动文档规则，两类合同根不被遍历读取。活动的来源清单仍严格验证目标文件存在；活动文档链接/索引/交付/版本检查继续。第11项治理回归同时证明“历史链接保留”和“活动坏链接仍拒绝”。

## 验证与限制

同步回归直接运行此实现，使用真实临时bare remote，验证推送、快进、分叉、人工索引、稳定期、stop/单实例、ignore、UTF8/UTF16凭据及出站历史拦截。真实项目运行证据另见 [本轮验证](../testing/2026-10-09-workspace-sync.md)。

单实例锁只协调同步进程；人工Git操作前先停止服务，避免同时操作索引的竞争。密钥模式检测不能证明所有资料已脱敏。文件系统快照不是多个应用共同事务；WIP提交不是任务验收。当前服务依赖登录会话、有效令牌和网络，断网/休眠等待恢复。

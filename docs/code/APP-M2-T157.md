## 一、改动文件与设计动机

### 1. 业务痛点与合规规范
根据 PRD v1.8 §5.10.6、§6.7、§7.3 及设计规范：
1. **敏感数据调阅留痕**：依据 PRD §5.4.5 与 §7.3 第 3 条，系统调阅身份证、银行卡等高敏完整值必须强制记录审计日志（调阅人、时间、网络环境 IP、业务理由），且业务理由必须达到 5 个字以上，不可留空或敷衍填写；
2. **章节排他编辑锁追踪**：依据 PRD §5.11.9 与 §7.3 第 13 条，章节排他独占编辑锁的获取、主动释放、超时释放以及管理员/负责人的强制接管必须全程可审计，接管需记录原因；
3. **模型密钥安全变更**：依据 PRD §7.3 第 16 条与技术规范，模型密钥配置的创建、更新、轮换与吊销必须记录审计，且密钥明文绝对不可在前端回显或日志中明文记录，只允许展示安全脱敏指纹（如 `sk-****8f92`）；
4. **纯只读不可篡改防护**：审计日志属于法律合规存证，对全量角色（含系统管理员与平台管理员）保持绝对只读，前端严禁提供任何修改、编辑、删除或清空接口；
5. **企业租户安全基线 (A-01)**：公司脱敏强规则不可关闭（PRD §6.9）；涉密项目强制使用内网本地模型断绝云端外发（PRD §6.4）；密码策略只能调严不可低于平台默认 8 位与 3 类字符（PRD §5.10.2）；编辑锁心跳三元数学约束校验（PRD §5.11.9）；集团管理员与公司管理员不同权限感知（非公司管理员隐藏编辑按钮）；公司停用必须提供二次强确认弹窗。

## 二、架构设计与核心模块

### 1. 审计日志核心引擎 (`audit-log-core.ts`)
- **数据结构契约 (`AuditLogEntry`)**：
  定义规范的结构化审计日志条目，涵盖发生时间、操作人 ID 与姓名、租户公司、操作动作（`AuditActionType`）、目标对象类型与编号、敏感调阅业务理由与合规检验标识、排他锁章节与接管理由、模型密钥变更事件与脱敏指纹、云端调用 token 消耗与耗时、IP 及执行结果。
- **调阅理由门禁校验 (`validateRevealReason`)**：
  校验调阅理由非空、去除首尾空格，严格检查字数是否 >= 5 字，不足 5 字返回合规拦截阻断。
- **密钥指纹脱敏函数 (`formatMaskedKeyFingerprint`)**：
  任何传入的原始密钥仅保留前缀和末尾 4 位（例如 `sk-****8f92`），彻底截断明文传输泄漏风险。
- **系统级只读断言 (`assertAuditLogReadOnly`)**：
  运行时防御性断言，拦截任何包含 `delete`、`edit`、`update`、`clear`、`truncate` 等篡改意图的操作。
- **多维组合检索过滤算法 (`filterAuditLogs`)**：
  支持多条件组合交集过滤：时间范围区间、事件大类、具体动作类型、操作人姓名/工号模糊匹配、项目 ID/名称匹配、租户匹配、执行状态（成功/失败）及综合全文检索。
- **统计汇总计算 (`computeAuditSummaryStats`)**：
  自动聚合总事件数、敏感调阅次数、编辑锁调度次数、模型密钥变更次数与综合执行成功率。

### 2. A-06 审计日志中心页面 (`AuditLogPage.tsx`)
- **只读防护提示条**：
  顶部展示安全合规 Alert 与水印说明，明确标示“不可篡改”、“只读归档”，告知所有用户日志受到平台级只读保护。
- **多维检索过滤栏**：
  包含时间范围选择器（RangePicker）、分类下拉（脱敏调阅/编辑锁/密钥管理/云端调用/业务资料）、操作动作选择器、操作人输入框、项目 ID / 关键词搜索框，以及重置按钮。
- **只读审计列表 Table**：
  - 发生时间：采用 SFMono 等宽字体格式化渲染（`YYYY-MM-DD HH:mm:ss`）；
  - 操作类型：带语义彩色 Tag（敏感调阅紫色、编辑锁橙色/蓝色、密钥管理青色、云端调用品红）；
  - 操作人：展示员工姓名与账号 ID；
  - 调阅理由列：对脱敏调阅记录突出显示调阅理由以及 `理由合规 (≥5字)` 状态 Badge；对排他锁突出显示接管理由；对模型密钥展示脱敏指纹；
  - 状态：成功（绿色 Tag）与失败（红色 Tag）；
  - 操作列：仅提供 [详情] 抽屉展开按钮，彻底杜绝任何行内编辑或删除操作。
- **只读审计存证详情抽屉 (Drawer)**：
  展示防篡改存证哈希、调阅字段、业务理由合法性核对结果、排他锁分册与章节调度、模型服务商、以及格式化 JSON 扩展上下文（纯文本只读）。

### 3. 企业多租户管理核心引擎 (`company-manage-core.ts`)
- **平台合规安全基线常量 (`PLATFORM_BASELINE`)**：
  定义平台统一安全基线：密码最少 8 位、字符至少 3 类、锁超时至少 5 分钟。
- **参数合法性强校验 (`validateCompanyComplianceSettings`)**：
  - 校验密码最少长度不可低于平台基线 8 位；
  - 校验密码字符类别不可低于平台基线 3 类；
  - 校验 `editor_autosave_seconds <= edit_lock_heartbeat_seconds`；
  - 校验 `edit_lock_heartbeat_seconds * 10 <= edit_lock_timeout_minutes * 60`；
  - 校验 `edit_lock_timeout_minutes > 5`；
  - 校验 `mask_strict_mode_enabled` 必须为 true，严禁关闭脱敏。
- **权限感知与按钮隐匿规则 (`canManageCompanySettings`)**：
  - `platform_admin`: 全局最高管理权，可开通、编辑和停用公司；
  - `company_admin`: 本公司管理员具备本公司基本信息与合规设置保存权限，但不可自我停用本公司；跨公司访问受阻；
  - `group_admin`: 跨公司只读审阅监管，严禁编辑任何公司合规参数，**所有敏感管理与保存按钮彻底隐藏**；
  - `viewer` / 其他角色: 纯只读浏览，隐藏管理按钮。
- **停用二次确认输入核验 (`validateDisableConfirmation`)**：
  校验用户输入的确认公司名称与目标租户名称必须完全一致，防止手误停用租户。

### 4. A-01 企业租户管理页面 (`CompanyManagePage.tsx`)
- **多租户切换与企业概况**：
  展示公司全称、18 位统一社会信用代码、所属集团、法人代表、租户资料库隔离空间与 RAGFlow 向量库空间状态；集团管理员与平台管理员可跨租户下拉切换。
- **安全合规参数配置四大页签**：
  1. 高敏脱敏规则页签：呈现“脱敏强规则已生效 · 严禁关闭”标识，支持标准模式（6+4）与严格模式（3+4）受控切换，手机号与银行卡脱敏保持锁定；
  2. 本地模型强制约束页签：涉密与敏感项目强制本地模型开关，切断敏感数据公网云端外发；
  3. 密码安全策略页签：密码最少位数（8~32）与至少字符类别数（3~4），只能调严不能调松；
  4. 编辑锁与自动保存联动页签：草稿自动保存间隔、心跳刷新间隔、锁超时时长，实时动态计算三元数学约束。
- **非管理员管理按钮隐匿**：
  当当前登录身份为集团管理员（`group_admin`）或只读角色时，界面显示权限感知告示条，同时“保存合规配置”、“停用公司租户”按钮自 DOM 中彻底隐藏或禁用。
- **停用租户二次确认 Modal**：
  点击停用弹出警示弹窗，明确告知所有用户登录将受阻但数据安全封存，强制要求输入完整公司名称进行二次比对确认。

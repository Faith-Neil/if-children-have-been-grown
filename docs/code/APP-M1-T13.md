# APP-M1-T13代码解释

日期2026-10-10，reference-writing-1，ISSUE-007。代码位于`frontend/web/src/`，实际操作见[写作验收](../testing/2026-10-10-writing-input.md)。

`WritingPlanReview.tsx`按章显示可选事实、要点和字数目标，必备事实固定展示。`writing-input.ts`从后台已保存方案恢复表单，提交明确选择和空目标，避免打开窗口丢掉上次选择。负责人确认时发送现有项目版本和重复请求标记；后台仍再次核对，按钮不能替代权限。

`WritingInputPreview.tsx`通过新增只读`writing-input`接口显示当前准备输入及阻断项；查看候选则使用候选自己保存的快照，不重新拿实时事实替换历史值。证据展示名称、版本、有效期和内容；事实展示变量、取值、原文页及摘录；省略项写明理由。只声明整章快照，当前没有逐段绑定或知识库检索。

`EditorPage.tsx`保留目录、正文、助手三栏，增加通用事实插入与输入快照抽屉。`candidateProblem`核对输入摘要和正文版本；旧候选可看来源但不能采纳。写入前再次读取工作区；内容先进入编辑缓冲，提交本节才成正式正文。未提交改动时禁止对已提交旧正文发送改写请求。

`insertFactToken`仅采用已确认、有值且完整ID的普通事实；SLA继续专用单位插入。事实指令拒绝时显示后台理由并给项目事实表/矩阵按钮。页面说明已校验输入、变量与单位，同时明确完整语义、段落来源、选区助手未完成。

回归同时覆盖原有13项页面函数、4项方案/候选/变量与5项来源写入保护函数，共22项。真实GUI验证包含选择900字方案、重新生成、来源快照、变更失效、取得编辑权、草稿/提交、源值指令拒绝、检查和两册下载。当前纯文本变量并非结构化编辑节点；完整角色、片段与段落来源仍后续实现。

采纳后的正文编辑继续携带候选原input_fingerprint；已有草稿保留自己的来源基准，页面重载或取得编辑权不能静默换成新基准。保存和提交都发送它，由后台同一事务再次比较。来源已改变时保留文字并给出重新核对入口；只有明确人工核对后才建立新基准。这不等于系统自动理解正文与原文是否语义一致。

## 改了什么以及为什么

为推进 ISSUE-037，在 `backend/bid-core/icg_demo/` 下新建只读检索客户端模块 `ragflow_client.py`，使用仓库中已有的 `httpx==0.28.1`，不增加任何第三方依赖。

客户端实现官方 HTTP 接口：`POST {base_url}/api/v1/retrieval` 以及健康检查 `GET {base_url}/api/v1/system/healthz`。

根据 [架构设计](../architecture/ragflow-retrieval-adapter.md) 约定：
1. 客户端使用环境变量注入的基址 `ICG_RAGFLOW_BASE_URL` 与密钥 `ICG_RAGFLOW_API_KEY`，支持通过 `RagflowConfig` 或 `RagflowRetrievalClient.from_env()` 进行装载。
2. 请求头注入 `Authorization: Bearer <API_KEY>`。密钥严格不进入日志、错误信息或异常堆栈。
3. 请求体只传递调用方注入的 `question`、`dataset_ids` 以及可选的 `rerank_id`。不调用数据集创建、上传、解析或同步接口。
4. 正确解析返回的 chunks 列表；官方成功信封中的 `code: 0` 为成功标准。
5. 零命中（`code: 0` 且 `data.chunks` 为空）在客户端中映射为 `skipped=True`、`skip_reason="zero hits"`，避免上层误认作有效证据命中。
6. 非零业务码（如 102）、HTTP 4xx/5xx、超时与传输异常均转换为明确的客户端异常类型。

## 入口和调用顺序

1. 客户端构造：
   - `client = RagflowRetrievalClient(base_url=..., api_key=..., timeout_seconds=...)`
   - 或 `client = RagflowRetrievalClient.from_env(environ=...)`
   - 支持通过 `transport: httpx.BaseTransport` 注入 MockTransport 或测试夹具。
2. 检索调用：
   - `result = client.retrieve(question="...", dataset_ids=["..."], rerank_id="...")`
   - 入参校验：`question` 必填非空字符串，`dataset_ids` 必填非空字符串列表，`rerank_id` 可选字符串。
   - 发起 HTTP POST 请求到 `{base_url}/api/v1/retrieval`。
3. 健康检查：
   - `status = client.health()`
   - 发起 HTTP GET 请求到 `{base_url}/api/v1/system/healthz`。根据官方发布文档，健康检查不携带 Authorization 请求头。

## 数据模型与结构

- `RagflowConfig`：包含 `base_url`、`api_key_env`、`api_key` 与 `timeout_seconds`。`_validate_base_url` 严格校验必须是 http(s) 绝对地址，去除末尾斜杠，保留网关前缀（如 `/gateway`），拒绝凭据、query 与 fragment。
- `RagflowChunk`：表示单条命中的切块，包含 `id`、`content`、`document_id`、`dataset_id` 与 `similarity`。
- `RagflowRetrievalResult`：检索结果容器，包含 `chunks: list[RagflowChunk]`、`doc_aggs: list[dict]`、`total: int`、`skipped: bool` 以及 `skip_reason: str`。

## 关键判断与异常分类

- `RagflowClientError`：所有客户端异常的基类。
- `RagflowHttpError`：HTTP 状态非 200（如 400、401、403、404、500、502、503）。包含 `status_code` 和服务端返回的错误消息，绝不泄露 API Key。
- `RagflowBusinessError`：HTTP 为 200 但响应 JSON 中 `code != 0`（如官方示例中的 `102` 参数缺失）。包含 `code` 和 `message`。
- `RagflowTimeoutError`：请求因网络延迟或对端无响应超时（捕获 `httpx.TimeoutException`）。
- `RagflowConnectionError`：传输层异常、网络拒绝连接（捕获 `httpx.TransportError`）。
- `RagflowResponseError`：响应体畸形（非有效 JSON、非字典结构、缺少 code/data 字段或 chunks 非列表）。
- 零命中处理：当 `code == 0` 但 `chunks` 列表长度为 0 时，返回 `RagflowRetrievalResult(chunks=[], total=0, skipped=True, skip_reason="zero hits")`。

## 离线纯洁性与真实端点隔离

在 `tests/backend/test_ragflow_client.py` 中：
- 默认全部测试均基于本机的 `fake_ragflow` 夹具（`FakeRagflow`）与 `httpx.MockTransport` 运行，无需外网或内网真实服务。
- 标记为 `@pytest.mark.live_ragflow` 的真实端点测试，必须在环境变量明确设置 `ICG_RUN_REAL_RAGFLOW_TESTS=1` 时才会触发，否则在 pytest 执行前自动跳过（理由为 `real RAGFlow endpoint tests require ICG_RUN_REAL_RAGFLOW_TESTS=1`）。

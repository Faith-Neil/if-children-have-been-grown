# AI-01：CI 假 OpenAI 兼容服务

- 对应任务 [AI-01](../tasks/AI-M0.md#ai-01)、[ISSUE-028](../../issues/ISSUE-028.md)、[交付](../delivery/AI-01.md)。
- 日期：2026-10-12。代码只在 `tests/backend/`。不改 `backend/bid-core`。PR：未创建。

## 改了什么以及为什么

托管 CI 没有密钥，也到不了内网。`FakeOpenAIChat` 用标准库在 `127.0.0.1` 的临时端口上接受 `POST /v1/chat/completions`，返回一条固定的合成助手文本。它把收到的请求头原样记下，并把路径末尾的 `/v1/chat/completions` 去掉，得到调用方实际使用的 `base_url`。带 `/gateway` 这类前缀时，前缀留在 `base_url` 里。

pytest 夹具 `fake_openai_chat` 在 `tests/backend/conftest.py`。现有 `OpenAICompatibleModelProvider` 只把 `base_url` 指到这个地址，不注入传输层。`create_app()` 不传适配器时仍是演示替身。

## 真实端点

标记 `live_model` 的测试会调用 `openai_provider_from_environment()`，从而访问环境里配置的真实地址。`ICG_RUN_REAL_MODEL_TESTS` 不是 `1` 时，该测试在调用前跳过，原因是 `real model endpoint tests require ICG_RUN_REAL_MODEL_TESTS=1`。`true` 或其他值同样跳过。CI 不设置这个变量。

打开时还要自行设置 `ICG_MODEL_PROVIDER=openai-compatible`、`ICG_MODEL_BASE_URL`、`ICG_MODEL_NAME`、`ICG_MODEL_IS_LOCAL`，以及密钥所在的环境变量（默认 `ICG_MODEL_API_KEY`）。

## 限制

不读取配置页，不改敏感项目的 409 `LOCAL_MODEL_REQUIRED`，不把 403 `SENSITIVE_PROJECT_REQUIRES_LOCAL_MODEL` 接到运行时。不加依赖。不改 `spec/openapi/demo-v1.json`，不改 `frozen_error_codes.py`。

# AI-06：代码解释

为什么有这个文件：说明 ISSUE-037 / AI-06 的证据候选改走 RAGFlow 检索适配器的实现细节与设计决策。

它解决什么问题：在 `backend/bid-core/icg_demo/retrieval.py` 中将 `EvidenceCandidateService` 的路径 B（公司知识库切片）和路径 C（历史投标库）改走注入的 `RagflowRetrievalClient`，保留路径 A（本地已确认规则），实现零命中（`skipped=True`）与异常时的安全回退降级，保证离线测试纯洁性与公司数据隔离。

- 对应任务：[AI-06](../tasks/AI-M0.md#ai-06)、[ISSUE-037](../../issues/ISSUE-037.md)、[交付](../delivery/AI-06.md)。
- 日期：2026-10-21。代码位于 `backend/bid-core/icg_demo/retrieval.py`，新增测试位于 `tests/backend/test_evidence_ragflow.py`。PR：未创建。

## 改了什么以及为什么

在 AI-03 建立检索层内存骨架与 AI-05 实现 `RagflowRetrievalClient` 的基础上，本卡推进 ISSUE-037 的闭环阶段：

1. **路径 B 与路径 C 改走 RAGFlow**：
   - 路径 B（方案切片）与路径 C（历史投标）在注入 `RagflowRetrievalClient` 时，调用 `client.retrieve(question=query, dataset_ids=..., rerank_id=...)`。
   - 路径 B 的候选标记为 `attachable=True, reference_only=False`。
   - 路径 C 的候选严格保持 `attachable=False, reference_only=True`，不可作为可附着证据。
2. **路径 A 保持本地已确认规则**：
   - 路径 A 依然直接基于本地已确认且非历史资料（`confirmed` 且 `record_type != "history"`）及查询词匹配规则，绝不经过外部 RAGFlow。
3. **路径 C 补齐查询词过滤**：
   - 响应 ISSUE-016 QA 签署中的观察项 O-1（P3）：在内存模式下补齐查询词过滤（`_matches_query(request.query, f"{bid.title} {bid.text}")`），避免无关历史标书被全部带出；在 RAGFlow 模式下由检索客户端将 `request.query` 作为 `question` 参数传入 RAGFlow 进行相关性检索。
4. **零命中与异常安全降级**：
   - 当 RAGFlow 返回 `skipped=True`（`skip_reason="zero hits"`）时，记录跳过原因并安全回退到路径 A，不将空列表误认作有效结果。
   - 当 RAGFlow 未配置、未配置该公司对应 dataset、或请求发生 HTTP 错误、业务错误、网络超时时，记录对应跳过原因（不泄露机密与正文），仅返回路径 A，整体服务与接口绝不崩溃。
5. **知识库关闭门禁**：
   - 当 `knowledge_base_enabled=False` 时，直接返回路径 A，记录 `knowledge base is off`，严格不触发任何网络请求。
6. **保持内存检索口兼容**：
   - 严禁删除内存检索口支持；当未注入 `ragflow_client` 但提供内存存储组件时，无缝走内存实现，保持既有 7 项单测 100% 通过。

## 入口和调用顺序

### 1. 服务初始化
```python
svc = EvidenceCandidateService(
    embedding=...,                 # 可选内存嵌入提供者
    rerank=...,                    # 可选内存重排提供者
    store=...,                     # 可选内存向量库
    ragflow_client=client,         # 可选注入的 RagflowRetrievalClient
    company_datasets={...},        # 公司到 RAGFlow 数据集标识（kb_dataset_ref）的映射
    company_history_datasets={...},# 可选：公司到独立历史投标数据集标识的映射
    rerank_id=...,                 # 可选重排器标识
    knowledge_base_enabled=True,   # 知识库开关，默认开启
)
```

### 2. 候选收集流程 (`collect(request)`)
1. 校验 `request.company_id`，空则抛出 `RetrievalError("company_id is required")`。
2. 本地计算**路径 A**：遍历 `request.library_items`，过滤属于本公司、状态为 `confirmed`、类型不为 `history` 且名称/正文匹配查询词的项。
3. 检查 `self.knowledge_base_enabled`：若为 False，直接返回 `CandidateResult(path_a, [SkippedPath("B", "knowledge base is off"), SkippedPath("C", "knowledge base is off")])`，绝不发起检索。
4. 执行**路径 B**：
   - 若注入 `ragflow_client`：解析本公司对应数据集 ID；向 RAGFlow 发起 `retrieve`；若 `skipped=True` 抛出 `RetrievalSkip("zero hits")`；将返回的 chunks 构建为 `EvidenceCandidate("B", chunk.id, request.company_id, chunk.content, attachable=True, reference_only=False)`。
   - 若未注入 `ragflow_client` 但有内存组件：走内存嵌入与向量检索，重排后返回。
   - 捕获 `RetrievalSkip` 并记入 `skipped`；捕获其他异常记为 `f"B failed: {type(exc).__name__}"`。
5. 执行**路径 C**：
   - 若注入 `ragflow_client`：解析本公司历史库（或本公司通用库）数据集 ID；向 RAGFlow 发起 `retrieve`；若 `skipped=True` 抛出 `RetrievalSkip("zero hits")`；将返回的 chunks 构建为 `EvidenceCandidate("C", chunk.id, request.company_id, chunk.content, attachable=False, reference_only=True)`。
   - 若未注入 `ragflow_client` 但有内存组件：对 `request.historical_bids` 按本公司及查询词匹配（`_matches_query`）过滤。
   - 捕获 `RetrievalSkip` 并记入 `skipped`；捕获其他异常记为 `f"C failed: {type(exc).__name__}"`。
6. 返回合并结果：`CandidateResult(path_a + path_b + path_c, skipped)`。

## 数据模型与结构

- `CandidateRequest`：扩展支持 `chunks` 与 `historical_bids` 默认空列表，支持请求级别的显式覆盖参数 `dataset_ids: list[str] | None`、`history_dataset_ids: list[str] | None` 与 `rerank_id: str | None`。
- `RetrievalSkip`：新增内部异常类，专门用于承载零命中（`zero hits`）、未配置（`RAGFlow is not configured` / `RAGFlow dataset not configured`）或空查询（`query is empty`）等受控跳过原因。
- `EvidenceCandidate`：路径 B 标为 `attachable=True, reference_only=False`；路径 C 标为 `attachable=False, reference_only=True`。

## 关键判断与异常分类

- **跨公司隔离**：严格只传入当前 `request.company_id` 名下注入的 dataset ID，绝不同时或混入其他公司的数据集。若返回的 chunk 携带异常 dataset ID，通过防御性校验抛出 `RetrievalError` 并降级。
- **零命中（`skipped=True`）**：RAGFlow 返回 `skipped=True` 或空 chunks 时，转化为 `RetrievalSkip("zero hits")`，放入 `result.skipped`，保留路径 A，不抛出非受控异常。
- **调用失败**：`RagflowHttpError`、`RagflowBusinessError`、`RagflowTimeoutError`、`RagflowConnectionError` 等均被捕获并转化为 `f"{path} failed: {type(exc).__name__}"`，敏感参数、URL 及正文不进入错误描述。
- **未配置降级**：服务未注入 `ragflow_client` 且无内存存储时，记为 `RAGFlow is not configured`；公司未配置数据集时，记为 `RAGFlow dataset not configured`。均安全回退至路径 A。

## 离线纯洁性与自动化测试

- 契约测试 `tests/backend/test_evidence_ragflow.py` 覆盖 15 项场景：
  1. 成功检索：路径 B/C 均命中，属性符合可附着/不可附着约定，网络调用仅发送一次 Bearer token、注入 dataset 及 rerank_id。
  2. 跨公司隔离：Alpha 与 Beta 严格隔离；未注册的 Gamma 自动降级并不发起请求。
  3. 独立历史库数据集：验证支持公司历史标书与普通知识库分数据集检索。
  4. 请求级别覆盖：验证请求入参中的 dataset_ids 和 rerank_id 优先级高于服务级默认配置。
  5. 零命中安全回退：`fake_ragflow.mode = MODE_EMPTY` 时保留路径 A 并标记 `zero hits`。
  6. HTTP 500 异常回退：保留路径 A 并标记 `B failed: RagflowHttpError`。
  7. 业务码非零异常回退：保留路径 A 并标记 `B failed: RagflowBusinessError`。
  8. 超时异常回退：保留路径 A 并标记 `B failed: RagflowTimeoutError`。
  9. 知识库关闭：`knowledge_base_enabled=False` 时严格无任何网络请求，标记 `knowledge base is off`。
  10. 未配置降级：空服务构造安全回退至路径 A。
  11. 内存模式路径 C 过滤：验证查询“机房巡检”返回对应历史标书，查询“完全无关”则过滤排除。
  12. 空查询处理：空白查询不向 RAGFlow 发送网络请求，标记 `query is empty`。
  13. 空公司 ID 拦截：校验空 `company_id` 抛出 `RetrievalError`。
  14. 越界数据集防御校验：模拟返回非目标数据集 chunk 时拦截并记录降级。
  15. 离线门禁：`@pytest.mark.live_ragflow` 默认自动跳过，保证 CI 纯洁性。

## 改了什么以及为什么

原来只有 `DemoModelProvider`，`is_real_model` 为 false。现在增加 `OpenAICompatibleModelProvider`，用来调用 OpenAI 兼容的对话接口。默认路径不变：不传适配器且不打开配置开关时，`create_app` 仍构造演示替身。这样现有测试和本地页面不会因为机器上残留环境变量去访问内网。

## 入口和调用顺序

进程入口是 `main.py` 底部的 `app = create_app(use_configured_model=True)`。开关打开后，`openai_provider_from_environment()` 读取 `ICG_MODEL_PROVIDER`。空值或 `demo` 返回 None，随后仍用演示替身。值为 `openai-compatible` 时构造真实适配器；其他值或缺少端点、模型名、`is_local` 时抛出 `ValueError`，进程不能带着错误配置继续假装模型可用。

业务调用顺序没有改。旧建议入口 `DemoService.suggest` 和章节生成 `WorkflowService.generate` 都先执行 `require_allowed_model`，再调用 `model_provider.suggest`。适配器内部用 httpx 发送一次 POST。返回的字符串回到原有校验；异常被原来的 `except` 转成 502 `MODEL_UNAVAILABLE`。

## 数据与状态

配置来自环境变量，不写入仓库：

| 变量 | 作用 |
|---|---|
| `ICG_MODEL_PROVIDER` | `demo` 或未设置保持替身；`openai-compatible` 才启用真实适配器 |
| `ICG_MODEL_BASE_URL` | 绝对 http(s) 源地址，不能带账号、密码、查询串或片段。实际路径是 `{base_url}/v1/chat/completions` |
| `ICG_MODEL_NAME` | 请求里的模型名 |
| `ICG_MODEL_API_KEY_ENV` | 存放密钥的环境变量名，默认 `ICG_MODEL_API_KEY`。密钥本身不在这个变量里 |
| `ICG_MODEL_TIMEOUT_SECONDS` | 默认 60，须大于 0 且不超过 600 |
| `ICG_MODEL_MAX_TOKENS` | 默认 1024，范围 1 到 1000000 |
| `ICG_MODEL_RETRIES` | 额外重试次数，默认 1，范围 0 到 5 |
| `ICG_MODEL_IS_LOCAL` | 只能是 `true` 或 `false`，没有默认值 |

请求体包含模型名、system 指令、user 正文、`max_tokens` 和 `stream: false`。有密钥时加 `Authorization: Bearer`。适配器不保存正文，也不改内存仓库。重定向关闭，避免把密钥随 302 带到别的地址。

## 关键判断与异常

敏感项目的判断仍在 `require_allowed_model`：真实模型且 `is_local` 不为 true 时返回 409 `LOCAL_MODEL_REQUIRED`，此时不会调用 `suggest`。未声明 `is_local` 的适配器也继续被拒绝。本适配器必须显式配置 true 或 false。

超时、传输失败和 HTTP 408/429/500/502/503/504 计入重试。401、403、404、302、200 但 JSON 不可解析、缺少助手文本、空文本或内容不是字符串，都立即失败。耗尽重试后抛出 `ModelCallError`，消息只有失败类别，不包含密钥、指令、正文或响应体。业务层不把该异常改写成演示建议。

## 验证与限制

验证见 [2026-10-12 记录](../testing/2026-10-12-openai-compatible-model.md)。测试注入 httpx `MockTransport`，不访问真实网络。

限制：没有调用公司内网；没有验证 Qwen 30B 的真实模型名、上下文和并发；没有实现嵌入、重排或向量库；没有选择业务数据库，也没有加入迁移工具。`is_local` 由部署配置声明，代码不能自行判断端点是否真的在内网。

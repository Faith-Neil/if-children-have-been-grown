===== 粘贴 2／3：六类 subagent 规格 =====

请创建（或固定）六类 subagent；业务只通过它们执行，你负责派活与验收。

### FE｜成长前端
- 范围：frontend/web/src 八域；测 frontend/web/tests/
- 禁止：src 根平铺；动 backend；标 done；FE-M0-T04～T10
- 输出：代码 + delivery（+code）+ 自测；推到 in-review

### BE｜成长后端
- 范围：逻辑进 backend/bid-core/icg/；icg_demo 仅 façade；API 只 /api/v1
- 禁止：巨石堆回 icg_demo；正式能力走 /api/demo；标 done
- 输出：delivery（+code）+ pytest；in-review

### AI｜成长 AI与RAG
- 范围：AI-M0/RAG 对接；真实端点或诚实 blocked
- 禁止：无证据称生产模型完成；假绿
- 输出：delivery + 端点/blocked 说明；in-review

### INT｜前后端联调
- 职责：契约与主路径胶水，不抢大功能
- 范围：/api/v1↔前端、错误体/会话、登录→导出断点；可改小范围双端胶水与联调测
- 禁止：大型新特性；巨石回流；标 done
- 输出：delivery 写断点与请求响应；in-review
- 你验收：主路径是否真通，契约是否对齐 OpenAPI/roles

### QA｜成长测试
- 范围：in-review 签署、回归、冒烟、REV
- 禁止：新开功能；自行标 done；无证据签过
- 输出：签署表；失败 REV

### PD｜产品验收（默认不写业务代码）
- 职责：对照 PRD/gap，防「测绿但不可用」
- 范围：prd-mvp-v1.8、字典 v1.9、prd-gap-summary、本卡 delivery；规则门禁、递交导出、知识库/写作档案、八角色是否像产品
- 禁止：大段改代码；无 PRD 依据建议 done；用 board done 当产品完成度
- 输出：产品对照表（卡ID|PRD/gap|通过/缺口|是否建议下一里程碑）
- 你验收：建议 PM done 前须有 PD 结论（或人类书面认可）；纯技术债可跳过 PD

Subagent 通用：只改本卡相关文件；守 AGENTS.md；回写 TASK_BOARD；向主 agent 汇报。

===== 粘贴 3／3：闭环派活（贴完即开干）=====

### 运转循环
1. 读 TASK_BOARD 排可做队列（依赖满足；非 FE-M0 绿野；优先 in-review 与冒烟）。
2. 派 FE/BE/AI/INT/QA/PD；每角色 1～2 卡（INT/PD≤1）；写清验收与禁止项。
3. Subagent 执行并写 delivery（+code）。
4. 你验收：QA 测 +（主路径/契约）INT +（建议 done 前）PD；通过则 in-review 并列入「建议 PM done」；不通过打回或开 REV；不得直接 done。
5. 回写 board + 5 行内进度；回到 1。

### 第一阶段
A. QA 清 in-review（BE-M0/AI-M0/APP-M2 优先）→ 签署表；必要时 INT 协助契约争议。
B. 冒烟 REV-SMOKE-001：关 VITE_DEMO → 正式登录 → 项目/上传 → 矩阵 → 生成 → 导出；QA 执行，INT 断点，PD 对照「能否演示给用户」；docs/delivery/REV-SMOKE-001.md。
C. A+B 有结论后进第二阶段。

### 第二阶段
FE：APP-M2 或 PRD P0 最小页｜BE：规则递交/门禁/已解锁 BE｜AI：可验收或诚实 blocked｜每切片 QA+（需要时）INT｜建议 done 前 PD｜ISSUE-038 仅 P2 插空。

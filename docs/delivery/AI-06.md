## 完成内容与变更文件

1. **证据候选服务重构**：在 `backend/bid-core/icg_demo/retrieval.py` 中改造 `EvidenceCandidateService`：
   - 路径 B（公司知识库方案切片）与路径 C（历史投标库）改走注入的 `RagflowRetrievalClient`。
   - 路径 A 依然直接执行本地已确认规则（`status == "confirmed"` 且 `record_type != "history"`），绝不经过外部 RAGFlow。
   - 跨公司隔离：严格按 `request.company_id` 解析本公司注入的 dataset ID，只将该 ID 传给 RAGFlow，绝不混用或跨越公司。
   - 路径 C 不可附着与查询词过滤：路径 C 候选标记为 `attachable=False, reference_only=True`；在内存模式下补齐查询词子串过滤，在 RAGFlow 模式下向检索接口发送 `question=request.query` 进行相关性检索，解决 ISSUE-016 QA 观察项 O-1（P3）。
   - 零命中与异常安全降级：捕获 `RagflowRetrievalResult.skipped == True` 并记为 `zero hits`；捕获所有客户端异常（HTTP 错误、业务错误、超时、连接异常），记录错误类型（不泄露密钥与正文），仅返回路径 A，接口整体绝不崩溃。
   - 知识库关闭门禁：`knowledge_base_enabled=False` 时直接返回路径 A 并记录 `knowledge base is off`，严格不触发任何网络请求。
   - 内存检索口兼容：保留内存嵌入、重排与向量表实现；当未注入 `ragflow_client` 时走内存逻辑，完全保证既有离线测试通过。
2. **自动化测试**：新增 `tests/backend/test_evidence_ragflow.py`，覆盖：
   - 路径 B 与路径 C 成功命中与属性校验（B 可附着、C 不可附着仅供参考）。
   - 跨公司隔离与未注册公司安全降级。
   - 独立历史库数据集与通用数据集支持。
   - 请求级别（`CandidateRequest`）显式指定数据集与 rerank_id 优先级覆盖。
   - 零命中（`MODE_EMPTY`）回退路径 A。
   - HTTP 500、业务码非零、网络超时异常降级回退路径 A。
   - 知识库关闭零请求门禁。
   - 未配置 RAGFlow 服务降级。
   - 内存模式路径 C 查询词相关性过滤（命中返回，完全无关词过滤）。
   - 空白查询词安全拦截。
   - 空 `company_id` 抛出 `RetrievalError`。
   - 越界数据集防御校验。
   - 真实端点探测（`@pytest.mark.live_ragflow`）离线默认跳过门禁。
3. **交付与代码文档**：产出本交付文件与 `docs/code/AI-06.md`，同步更新任务看板、AI-M0 任务卡与 ISSUE-037。

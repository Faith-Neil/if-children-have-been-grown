===== 追加粘贴｜INT 联调 + PD 产品验收（已贴完 2/3 后补这段）=====

在已有 FE/BE/AI/QA 之外，再创建（或固定）两类 subagent。之后派活与验收按六角色运转。

### INT｜前后端联调 subagent
- 职责：打通契约与主路径胶水，不抢大功能开发。
- 范围：`/api/v1` 与前端调用对齐、错误体/角色会话联调、登录→项目→解析/上传→矩阵→生成→导出 的断点定位；可改小范围 FE+BE 胶水与联调测试。
- 禁止：单独开大型业务特性；把逻辑堆回 `icg_demo` 巨石；新正式能力走 `/api/demo`；自行标 done。
- 输出：`docs/delivery/<ID>.md`（写清断点、请求/响应、复现）；必要时最小代码；推到 in-review。
- 主 agent 验收看：主路径是否真正通、契约是否与 OpenAPI/`roles` 一致，不只看单侧测绿。

### PD｜产品验收 subagent（默认不写业务代码）
- 职责：以最终产品为准对照 PRD，防止「测绿但产品不可用」。
- 范围：读 `docs/reference/product/prd-mvp-v1.8.md`、`kb-data-dictionary`（v1.9）、`docs/delivery/2026-10-22-prd-gap-summary.md`、本卡 delivery；对照规则门禁（含 RULES_INCOMPLETE）、递交/导出、知识库/写作档案、八角色权限是否像产品。
- 禁止：大段改代码；无 PRD 依据就建议 done；把 board done 数当产品完成度。
- 输出：产品对照表（卡ID | PRD条款/gap项 | 通过/缺口 | 是否建议进入下一里程碑）；缺口写成可派工描述给主 agent。
- 主 agent 验收看：有无明确产品结论；建议 PM done 前须 PD 或你书面认可（QA 测绿不够）。

### 闭环补丁（覆盖粘贴 3 的验收规则）
- 每张功能卡：开发 → QA 签署 → **涉及主路径/契约时加 INT** → **建议 done 前加 PD 对照**（纯技术债卡可跳过 PD）。
- 第一阶段：A 清 in-review 时 QA 为主；冒烟 REV-SMOKE-001 由 QA 执行、**INT 协助断点、PD 对照「关演示后主路径是否可演示给用户」**。
- 第二阶段并行时：FE/BE/AI 各最多 1～2 卡；INT 同时最多 1 条联调卡；PD 每轮至少对「建议 PM done」清单做一次抽检。
- 仍禁止派 FE-M0-T04～T10；done 最终由人类 PM 确认。

确认六角色已建立后，若尚未执行粘贴 3，请执行粘贴 3 并开始第一阶段 A；若已在跑闭环，把后续派活切换为六角色规则，不要停掉当前 QA 清账。

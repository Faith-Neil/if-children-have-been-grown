# 资料表单已读依据验证

日期：2026-10-11（北京时间）。关联[ISSUE-008](../../issues/ISSUE-008.md) / APP-M1-T16；完整资料治理继续ISSUE-007 / APP-M2-T046～050。全部账号、资料和正文是合成数据。

## 真实缺陷与判定

独立临时TestClient复现原实现：A打开旧资料，B保存新正文，A第一次保存409；页面刷新公司版本但保留旧正文，A再次保存携带新公司版本，返回200并覆盖B。后台不能判断人是否真的核对过，只能检查请求声称的版本；页面因此必须保存实际读取的原版本，不能在错误后自动升级。

独立代码审查还发现：核对窗口如果只使用页面缓存，B在窗口打开后再次修改，A会载入过期内容并丢失本地填写。载入确认须真实重新GET，再核验所展示的公司版本和记录依据；读取失败或再次变化都不能替换文字。

## 已执行后台验证

新增[真实接口回归](../../tests/backend/test_library_basis.py)，调用实际应用路由，专项13项通过。最终由主负责人执行全后台229项通过（75.57秒）；此前223项是加入服务模板专项前的阶段结果。命令：`.venv/Scripts/python.exe -m pytest tests/backend/test_library_basis.py -q`及`... -m pytest tests/backend -q`。只有已有Starlette/httpx弃用提示。

覆盖旧公司版本创建/修改409、同公司另一条资料变动、完整仓储无副作用、显式重新读取核对最新正文后成功、重复请求只写一次、复用标记但改内容/版本/动作拒绝、跨公司两角色404、只读创建/修改403、缺版本/标记428。所有拒绝同时比对真实仓储，资料、版本、审计、收据和项目不变。

另新增[服务模板真实接口回归](../../tests/backend/test_sla_template_basis.py)，专项6项通过：旧30分钟表单无法用旧版本覆盖协作者90分钟；旧完整数组不能覆盖新增、删除或数值变化；明确读取核对后保留90分钟并合法补充说明；跨公司404和只读403；拒绝时全仓储无副作用。以上包含在最终实际229项中。

本次未修改生产后端或新增接口；上述证明现有后台的版本与原子写入保护，不证明缺失的负责人权限、ACL或审核流程。

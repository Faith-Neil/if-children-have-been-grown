## 现象与证据

生产门禁 [ISSUE-005](ISSUE-005.md) 仍 blocked。当前后台默认是内存仓库和演示模型替身。公司候选的对话模型是内网本地 Qwen 30B，经 OpenAI 兼容 HTTP 接口提供。托管 CI 不能访问该内网。嵌入、重排、向量库、业务库和日志要求都还没有用户结论。

本文件只列出可选项和需要用户回答的问题。它不选择 PostgreSQL、MySQL、SQLite、pgvector 或任何其他数据库，也不宣布 Qwen 端点已经接通。

## 可选项

### 对话模型

| 选项 | 说明 | 当前状态 |
|---|---|---|
| 公司内网本地 Qwen 30B | 通过 OpenAI 兼容的 `POST {base_url}/v1/chat/completions` 提供 | 候选，未决定，端点未入库 |
| 继续使用演示替身 | 现有 `DemoModelProvider`，不访问网络 | 代码默认值，直到显式配置真实适配器 |
| 公司另行指定的本地模型 | 仍走同一兼容接口，具体名称待用户给出 | 未决定 |
| 云端模型 | 是否允许尚未回答；敏感项目现有门禁仍拒绝未声明为本地的真实模型 | 未决定 |

### 嵌入、重排和向量库

嵌入模型名称和维度未定。重排可以暂不启用、使用本地重排，或使用兼容接口；三者都未选。向量库存放要和业务库一起决定，避免先锁定一种库之后放不下向量。可选方向包括：与业务库同库、公司已经在运行的独立向量服务、或在嵌入和知识库格式确定前继续不做向量库。本记录不指定其中任何一项。

### 业务数据库

业务库与向量库同一次决定。迁移工具（例如 Alembic）推迟到数据库选定之后再引入。单元测试继续使用现有内存实现。

| 选项 | 说明 | 当前状态 |
|---|---|---|
| PostgreSQL 16 | pgvector 可以与业务库共用同一个数据库。项目经理建议采用此项 | 仅是建议，用户尚未决定，本记录不采纳 |
| MySQL 8 | 若选用，向量库需要另行安排，不能假定具备 pgvector | 未决定 |
| SQLite | 只适合单机演示，不能当作多人生产库 | 未决定 |
| 公司已规定的数据库 | 若存在强制标准，以该标准为准，并同时说明向量放在哪里 | 未决定 |

### 内网访问与验证

托管 CI 不能访问公司内网，因此不能把真实端点调用放进当前 CI。

| 选项 | 说明 |
|---|---|
| 手工内网联调 | 在能访问内网的环境执行，并保存可复核证据：时间、合成数据、命令、结果和失败。凭据不入库 |
| 内网自建 runner | 由位于内网的 runner 执行需要内网的检查。凭据放在 runner 环境，不写入仓库 |

两项都未选定。在选定之前，自动化测试只使用假 HTTP 服务或假传输，不调用真实端点。

## 请用户决定的问题

1. 对话端点的 base URL 是什么？是否只在内网可达？
2. 精确模型名是什么？是否就是待确认的 Qwen 30B 服务名？
3. 上下文长度是多少？
4. 认证方式是什么？密钥放在哪个环境变量？是否允许空密钥的内网服务？
5. 允许的并发是多少？超时和失败重试的上限是多少？
6. 是否允许云端模型？敏感项目是否一律禁止云端？
7. 嵌入模型的名称和向量维度是什么？
8. 是否需要重排？若需要，用本地模型还是兼容接口？
9. 公司是否已有向量库或业务库必须沿用？
10. 知识库的格式、规模和扫描件 OCR 需求是什么？
11. 访问隔离怎样划分：公司、项目、敏感项目是否分开存储和调用？
12. 敏感项目的定义是什么？哪些字段或项目类型算敏感？
13. 日志怎样才符合要求？提示词、回复和密钥是否禁止落日志？
14. 业务库选 PostgreSQL 16、MySQL 8、仅单机演示的 SQLite，还是公司已规定的库？
15. 向量是否与该业务库同库？项目经理建议的 PostgreSQL 16 加 pgvector 是否采纳？

解除阻塞的条件：用户逐项给出决定，或明确写出哪些项继续推迟以及推迟期间禁止做的实现。只有决定记录下来之后，才能把对应选型写进 PRD、路线图和架构的业务正文。

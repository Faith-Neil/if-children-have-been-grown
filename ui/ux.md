# 智能投标系统 UI / UX 规范

## 1. UX 核心原则

### 1.1 工作流优先

不要围绕“AI 能做什么”设计页面。

围绕用户任务设计：

```text
负责人：
看进度、风险、待办

编写人员：
确认、生成、编辑、复核

资料管理员：
维护可引用企业事实
```

### 1.2 AI 不静默修改

人工编辑阶段所有 AI 修改必须：

```text
生成建议
  ↓
用户预览
  ↓
Diff
  ↓
确认
  ↓
写入正文
```

### 1.3 所有重要内容可追溯

用户必须能够回答：

- 这段谁写的
- 谁改过
- 引用了什么
- 为什么出现问题
- 当前属于哪个版本

### 1.4 不把复杂状态全部塞进颜色

颜色只表达大类：

- 灰：未开始
- 蓝：处理中
- 橙：需人工
- 绿：完成
- 红：异常

精确状态靠文字。

---

# 2. 页面布局

## 2.1 全局

桌面端优先。

建议内容宽度：

- 普通管理页：1200～1440px
- 编辑台：尽可能使用全宽
- 大型表格：支持横向滚动或列固定

## 2.2 项目页

顶部固定：

```text
项目名称
项目状态
截止时间
负责人
```

下面为项目二级导航。

避免每个页面重复大面积项目信息。

---

# 3. 编辑台布局

推荐：

```text
┌──────────┬──────────────────────┬─────────────┐
│章节目录   │ 正文编辑区           │ 问题 / 来源 │
│          │                      │ AI助手      │
└──────────┴──────────────────────┴─────────────┘
```

建议：

- 左侧：240px
- 中间：最小 700px
- 右侧：360～420px

### 小屏

- 左侧章节树可折叠
- 右侧 AI 助手改成 Drawer
- 正文始终保留最大阅读宽度

---

# 4. 首页 UX

首页不要做传统 BI Dashboard。

第一屏优先：

```text
我的待办
临近截止
阻断问题
进行中项目
```

统计趋势放第二屏。

待办必须点击即可进入对应处理页面。

---

# 5. 项目概览 UX

第一屏必须看到：

- 完成度
- 截止时间
- 技术标状态
- 商务标状态
- 阻断问题
- 待人工章节
- 缺失材料

避免负责人进入 3～4 个页面才能判断风险。

---

# 6. 响应矩阵 UX

响应矩阵使用高密度表格，但必须提供：

- 列固定
- 筛选
- 快速搜索
- 行展开 / Drawer
- 只看风险
- 只看未覆盖
- 只看高分项

状态建议：

```text
✓ 已完整响应
△ 部分响应
! 缺证明
× 未响应
```

不要使用 10 种颜色表示细微状态。

---

# 7. 招标文件 UX

左：

- 文件目录 / 页码

中：

- 原文

右：

- 抽取结果 / 条款信息

从任何评分项、检查问题或响应矩阵，都可以反向定位原文。

---

# 8. 章节树 UX

章节节点显示：

```text
章节名

状态

问题数量

负责人
```

例如：

```text
2.2 数据库巡检
待人工 · 3 个问题
李四
```

当前章节明显高亮。

---

# 9. 编辑器 UX

## 9.1 正文保持干净

不要一直显示大量技术标签。

段落元数据只在以下场景出现：

- Hover
- 选中段落
- 用户主动打开来源
- 当前段落有问题

## 9.2 段落操作

Hover 左侧显示：

```text
⋮
```

菜单：

- AI 修改
- 查看来源
- 查看问题
- 查看修改记录
- 复制段落链接

---

# 10. 来源 UX

来源不要做成一串内部 ID。

应该显示人能理解的信息：

```text
招标文件 · 第28页

XX银行数据库维保项目

项目事实 · 故障响应时间
```

点击后：

- 查看原文
- 查看资料详情
- 查看事实来源

---

# 11. AI 助手 UX

## 11.1 默认状态

输入框上方提供 3～4 个快捷操作：

```text
解释本章
还有什么遗漏
查找相关案例
查看检查问题
```

## 11.2 知识库开关

开关必须清楚：

```text
知识库：开启
```

关闭后明确提示：

```text
本次回答不使用企业知识库
```

## 11.3 选区状态

用户选中文字后浮层：

```text
优化表达
补充细节
增加事实
压缩内容
更多…
```

---

# 12. AI 建议卡

每条建议必须能快速比较。

建议结构：

```text
方案 1
更简洁

正文预览……

来源 2

[查看差异]
[替换]
[插入]
```

默认只展开第一条。

避免同时展示 3 大段全文造成认知负担。

---

# 13. Diff UX

必须明确区分：

- 新增
- 删除
- 保留

Diff 弹窗同时显示：

- 原文
- 修改后
- 来源
- 修改原因

操作：

```text
取消
确认写入
```

不提供“自动全部接受”。

---

# 14. 自动保存 UX

只在编辑器右上角轻量显示：

```text
已保存

保存中…

保存失败
```

保存成功不弹 Toast。

保存失败才明显提示，并提供“重试”。

---

# 15. 编辑锁 UX

他人正在编辑时：

页面不要直接让用户修改。

显示：

```text
李四正在编辑

最后活动 14:35

当前为只读模式
```

可操作：

- 刷新状态
- 强制接管（有权限时）

强制接管弹窗必须填写原因。

---

# 16. 锁定内容 UX

不要只显示：

> 不可编辑

要告诉用户：

```text
该内容由项目事实生成

[前往项目事实表修改]
```

或：

```text
该段为招标原文引用

如需调整，请修改引用方式，而不是原文内容。
```

---

# 17. 问题 UX

问题按：

- 严重
- 警告
- 提示

显示。

问题卡至少包含：

- 规则
- 问题描述
- 章节
- 段落位置
- 建议处理方式
- 负责人

操作：

- 打开编辑台
- 转人工
- 标记已处理
- 重新检查

---

# 18. 风险 UX

风险不是所有 Warning 的简单汇总。

项目负责人优先看到：

```text
会影响导出的阻断问题

临近截止仍未完成章节

缺失证明材料

额外承诺

负偏离

定稿后又修改
```

普通写作风格提示不要和这些风险同层级。

---

# 19. Toast / Modal / Drawer 使用规范

## Toast

适合：

- 保存失败
- 操作成功
- 网络异常

不适合：

- 长文本解释
- 业务阻断
- 需要用户决策的问题

## Modal

适合：

- 删除确认
- 回退确认
- 强制接管
- Diff 确认
- 分册解锁

## Drawer

适合：

- 来源详情
- 问题详情
- 响应矩阵行详情
- 资料详情
- AI 助手（中等屏幕）

---

# 20. Empty State

避免空白页面。

例如没有项目：

```text
还没有投标项目

创建项目后，可从招标文件开始完成响应、生成和检查。

[创建第一个项目]
```

没有检查问题：

```text
当前没有待处理问题

✓ 当前检查已通过
```

---

# 21. Loading UX

长任务不要只放 Spinner。

例如章节生成：

```text
正在执行规则检查…

当前步骤 3 / 5
```

文件解析：

```text
正在解析招标文件

已完成 72 / 128 页
```

如果后端无法提供百分比，则显示当前阶段。

---

# 22. 表单 UX

企业资料和配置页面：

- 必填字段明确
- 高风险字段给说明
- 单位和输入框绑定
- 默认值可见
- 修改后提示是否影响已有项目

涉及金额、人员身份、额外承诺等敏感字段，必须有更明显的确认提示。

---

# 23. 搜索 UX

全局搜索建议 `Ctrl + K` 打开。

结果分组：

```text
项目
章节
评分项
人员
案例
资质
方案片段
```

支持键盘上下选择和 Enter 跳转。

---

# 24. 可访问性

至少满足：

- 状态不能只靠颜色
- 键盘可操作主要功能
- Focus 状态清晰
- Tooltip 不承载唯一信息
- 表单错误有文字说明
- Diff 增删有文字 / 图标辅助

---

# 25. 文案风格

系统文案：

- 简短
- 业务化
- 不使用模型术语教育用户

推荐：

```text
正在生成章节
正在检查本次修改
需要人工确认
```

不推荐：

```text
Agent 正在执行推理链
LLM 正在调用工具
Embedding 检索中
```

---

# 26. 移动端

一期不提供完整正文编辑。

移动端只支持：

- 我的待办
- 项目状态
- 风险查看
- 问题查看
- 资料审批
- 通知

编辑器、响应矩阵、复杂 Diff 保持桌面端。

---

# 27. UI 优先级总结

最高优先级：

1. 项目概览
2. 响应矩阵
3. 章节状态
4. 编辑台
5. AI 修改确认
6. 问题中心
7. 版本与来源
8. 导出

设计目标不是“AI 感强”，而是：

> 用户清楚知道当前做什么、系统做了什么、内容从哪里来、下一步应该做什么。

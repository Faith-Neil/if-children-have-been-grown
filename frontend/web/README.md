为什么有这个文件：说明按照 ICG 设计资料重建的正式页面如何运行，以及哪些功能已经接通后台。

它解决什么问题：避免把旧静态原型、后台验证页面和正式产品页面混为一谈。

# ICG 产品页面

页面按 `ICG/frontend doc/design-spec-v1.1.md`、`frontend-handoff-v1.md` 与 6 张原图保留导航、项目摘要、分册卡、解析三栏、矩阵、编辑三栏及检查列表。所有业务操作使用同源后台接口，演示账号与合成数据便于在不接真实模型和数据库时验证操作链路。

## 运行

需要 Node.js 24 与 pnpm。先在本目录运行 `pnpm install --frozen-lockfile`，然后运行 `pnpm build`；后端将 `dist` 作为根页面提供。开发时先启动后端 8710，再运行 `pnpm dev`，开发页面 5173 将 `/api` 转发到后台。登录凭证只保留当前页面，不写浏览器长期存储。

`package.json` 登记依赖与构建命令；`pnpm-lock.yaml` 固定依赖的实际版本；`tsconfig.json` 保证页面字段和代码经过类型检查。JSON 不允许注释，所以这些文件的作用在本说明登记。

## 当前边界

主链路页面连接项目、招标上传、解析人工确认、响应与证据、两册章节编辑、检查与 Word 导出。模型建议采用演示结果；正文必须经过差异确认并提交，草稿不能用于导出。资料库、任务页只展示已接通的真实能力。其余管理和设计规定的高级能力均显式标识待实现，不能把页面外壳当作功能完成。
